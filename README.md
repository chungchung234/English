# 시시콜콜 — 링크로 시작하는 영어 통화

휴대폰·PC 브라우저에서 링크로 접속하는 가벼운 영어 말하기 서비스입니다. 이메일 로그인, 음성 역할극, 대화 자동 저장, 개인별 장기 이력, 통화·주간 분석을 제공합니다. 특정 AI 채팅 앱 설치나 사용자별 API 설정은 필요하지 않습니다. 정적 웹 호스팅과 관리형 Supabase를 사용하므로 상시 서버를 직접 운영하지 않습니다.

**현재 상태:** [공개 사이트](https://chungchung234.github.io/English/)와 Supabase DB·함수 배포가 완료됐습니다. [실제 배포 검증](https://github.com/chungchung234/English/actions/runs/42639444223)에서 Mia·Alex·Juno 각각의 합성 음성 입력, 실제 WebRTC 연결·전사·응답, 자동 저장·피드백, 새로고침 후 이력 복원, 상대별 기억 분리, 계정 간 격리, 상위 모델 주간 분석이 통과했습니다. 검증용 임시 계정은 테스트 후 정리합니다. **일반 이용자의 이메일 로그인 전달과 재해 복구까지 완료된 운영 서비스로는 아직 표시하지 않습니다.**

## 구성

- `dist/index.html`: CSS·JavaScript를 포함한 이미지·아이콘을 포함한 약143KB 정적 웹 페이지. 방문자에게 연결 설정을 요구하지 않으며 운영자가 빌드 시 공개 연결 정보를 한 번 설정합니다.
- `web/`: 모바일 중심 한국어 UI, 통화·복습·기록 탭, 이메일 코드 로그인, WebRTC 통화, 피드백, 전체 JSON 백업/복원.
- `src/outbox.js`: IndexedDB 복구 대기열. 클라우드 확인 전 삭제하지 않으며 동일 UUID로 재전송.
- `supabase/migrations/`: 사용자별 RLS, 원문 전사, 분석 출처, 중복 방지, 비용 요청 예산, 전체 이력 검색.
- `supabase/functions/coach/`: 인증·허용 이메일·출처 검사, 음성 API 연결, 분석, 기억 검색. 비밀 API 키는 이 함수에서만 사용.

## 모바일 디자인과 대화 상대

앱 이름과 이미지 로고는 모두 **시시콜콜**입니다. 승인된 밝은 녹색 화면을 기준으로 여백을 확보하고, 하단 내비게이션과 통화 제어에 반투명 글래스를 적용했습니다. 사용자가 지정한 `liquid-glass` 스킬은 `.agents/skills/liquid-glass/SKILL.md`에 보존했습니다. 원본 스킬의 SwiftUI API 대신 웹의 `backdrop-filter`와 접근 가능한 HTML 컨트롤로 원칙을 적용합니다. [시각 검증 보고서](design-qa.md)에 선택된 시안과 브라우저 화면 비교가 있습니다.

| 상대 | 성격 | 음성 |
| --- | --- | --- |
| Mia | 편안하고 다정한 여자 친구 | `marin` |
| Alex | 차분하게 이야기를 들어주는 남자 친구 | `cedar` |
| Juno | 가볍게 농담하는 장난스러운 친구 | `verse` |

상대별로 대화·기억 검색·피드백·주간 분석의 맥락을 분리합니다. 목소리와 성격은 서버에서 저장된 회차의 상대를 확인해 선택합니다. 기존 기록은 Alex에 이어집니다. 전체 백업은 세 상대의 기록을 모두 포함하며 복원 시 상대 구분도 보존합니다. 실제 공개 배포 검증은 세 상대 각각의 음성 통화·자동 저장·새로고침·기억 분리를 검사합니다.

## 모델 티어링

| 기능 | 기본 모델 | 호출 시점 |
| --- | --- | --- |
| 음성 대화 | `gpt-realtime-mini` | 통화 중 |
| 음성 전사 | `gpt-4o-mini-transcribe` | 사용자 발화 |
| 통화 후 교정 | `gpt-4.1-mini` | 저장 후 회차당, 동일 원문은 재사용 |
| 최근 7일 분석 | `gpt-4.1` | 사용자가 요청할 때만, 동일 원문은 재사용 |

음성·교정·분석 모델은 `VOICE_MODEL`, `COACH_MODEL`, `ANALYSIS_MODEL`로 바꿀 수 있습니다. 계정별 실제 모델 접근과 음성 품질은 실연결로 검증해야 합니다. 모델 티어링은 호출 정책이며 실제 절감액을 측정한 결과가 아닙니다. ChatGPT/Claude 구독과 API 과금은 별도입니다.

## 로컬 개발과 검증

Node.js 24, Python3이 필요합니다. 개발 의존성은 lockfile로 고정합니다.

```sh
npm ci --cache /workspace/.npm-cache
npm run check
npm test
npm run test:browser
npm run build
```

브라우저 테스트는 Chromium을 사용합니다. `/usr/bin/chromium`이 아닌 경우 `CHROMIUM_PATH`를 지정하세요. 브라우저 테스트의 음성·외부 API 응답은 모의 값이며 실제 음성 연결을 검증하지 않습니다. DB 테스트는 PGlite PostgreSQL 엔진에서 실제 SQL·RLS·복원·분석 경계를 검사합니다.

`npm run dev`는 내부 개발 검증용 정적 파일 서버입니다. 운영 때 이 서버를 실행할 필요는 없습니다. 각 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하고 별도 Git worktree를 만들지 않습니다.

## 새 Supabase 프로젝트 연결

현재 선택한 프로젝트: `domkmxmwmihcfadophfg`

1. https://supabase.com/dashboard/project/domkmxmwmihcfadophfg 에서 연결합니다.
2. **API / Connect**에서 Project URL과 publishable 또는 anon 공개 키를 확인합니다. service_role/secret 키를 프런트 화면에 넣지 마세요.
3. **Authentication → Email**에서 이메일 OTP를 켜고 이메일 템플릿에 `{{ .Token }}` 코드가 표시되게 설정합니다. 실제 메일 전달·코드 로그인은 직접 검증해야 합니다. 공개 사용자 가입을 위해 운영용 SMTP를 구성하고 운영자 외 이메일로 코드가 전달되는지 검증해야 합니다. 기본 이메일 발송만으로 모든 방문자에게 전달된다고 가정하지 않습니다.
4. **Edge Functions → Secrets**에서 아래 항목을 저장합니다.
   - `OPENAI_API_KEY`: 실제 OpenAI API 키. 여기에 직접 안전하게 입력합니다.
   - `ACCESS_MODE=public`: 기본값. 누구나 이메일을 인증해 가입할 수 있습니다. 초대제로 운영할 때만 `ACCESS_MODE=invite`와 `ALLOWED_EMAILS`를 설정합니다.
   - `ALLOWED_ORIGINS`: 배포한 웹사이트의 정확한 origin. GitHub Pages 기본 도메인을 사용한다면 `https://chungchung234.github.io`입니다. 경로나 마지막 `/` 없이 입력합니다.
   - 선택: `VOICE_MODEL`, `COACH_MODEL`, `ANALYSIS_MODEL`.
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 Supabase 런타임 기본 바인딩을 사용합니다. 브라우저에 노출하지 않습니다.
5. 관리 토큰은 https://supabase.com/dashboard/account/tokens 에서 발급하고, 채팅 대신 클라우드의 `SUPABASE_ACCESS_TOKEN` 보안 항목에 저장합니다. 프로젝트와 DB 쓰기, 함수 배포 권한이 필요합니다. Supabase CLI 3 기준 `database_write`, `edge_functions_write`, `projects_read` 등 작업에 필요한 범위만 부여하세요.
6. `SUPABASE_PROJECT_REF=domkmxmwmihcfadophfg` 환경 설정을 적용한 후 배포합니다.

```sh
python3 scripts/deploy.py
python3 scripts/deploy.py --apply
```

첫 명령은 권한·연결을 검증하지 않는 로컬 필수 변수 검사입니다. 두 번째 명령은 HTTPS Management API로 원자적 DB 마이그레이션을 적용하고 고정된 CLI로 함수를 배포합니다. DB 포트나 로컬 Docker 서비스는 필요하지 않습니다. 관리 API 배포는 GitHub Actions에서 실제 프로젝트로 검증했습니다. 같은 마이그레이션은 체크섬으로 재적용을 막습니다.

`verify_jwt=false`는 최신 publishable 키와의 게이트웨이 호환을 위한 설정입니다. 함수 자체는 모든 요청의 실제 사용자 JWT를 Supabase Auth에서 검증하고, 이메일 인증과 정확한 origin을 검사합니다. 초대 모드에서만 이메일 allowlist도 검사합니다. 인증 없는 AI 호출을 허용하지 않습니다.

## 공개 웹 배포 (운영자만 한 번 설정)

기존 저장소의 GitHub Pages를 기본 정적 호스팅으로 사용합니다. 다른 정적 호스트에도 `dist/`를 그대로 올릴 수 있습니다.

1. 저장소 **Settings → Secrets and variables → Actions**에 연결 설정을 저장합니다. `SUPABASE_ACCESS_TOKEN`을 Repository secret으로 저장하면 CI가 공개 키 조회와 Supabase 백엔드 배포를 진행합니다. OpenAI 키는 기존 Supabase 보안 설정을 그대로 사용합니다. 아래 공개 변수를 직접 설정하는 방법도 지원합니다.
   - `PUBLIC_SUPABASE_URL=https://domkmxmwmihcfadophfg.supabase.co`
   - `PUBLIC_SUPABASE_KEY`: Supabase의 publishable 또는 anon 공개 키. OpenAI 키나 service_role 키를 넣지 않습니다. 빌드가 비밀 키를 거부합니다.
2. 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 지정합니다.
3. 소스를 `main`에 반영하면 `.github/workflows/pages.yml`이 공개 연결 정보를 포함한 정적 페이지를 빌드·게시합니다. 소스는 `main`에 반영됐습니다. Pages 자동 활성화도 시도하며 저장소 권한이 부족하면 위 설정을 직접 지정해야 합니다. 첫 실제 CI 실행은 공개 연결 정보 누락으로 빌드 단계에서 중단됐으며, 이후 CI는 Repository secret/variable 양쪽을 지원합니다.
4. Actions 배포 결과에 표시된 실제 URL에서 이메일 로그인과 마이크 허용을 검증합니다. HTTPS가 필요합니다.

직접 빌드하려면 같은 `PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_KEY` 환경 변수를 설정한 뒤 실행합니다.

```sh
npm run build -- --require-config
```

빌드는 외부 JavaScript 런타임 의존성 없이 `dist/index.html` 하나로 앱을 묶고, 인라인 코드에 CSP 해시를 적용합니다. 방문자는 API 설정 화면 없이 이메일 로그인부터 시작합니다. Supabase 관리 토큰이 있으면 공개 키는 관리 API에서 자동 조회하며 브라우저에 관리 토큰을 포함하지 않습니다. 연결 정보 없이 로컬 빌드를 하면 ‘서비스 준비 중’ 화면이며, CI의 `--require-config`는 설정 누락 시 게시를 중단합니다.

세 키는 용도가 다릅니다: Supabase publishable 키는 공개 앱 연결용, `OPENAI_API_KEY`는 서버의 AI 호출용, `SUPABASE_ACCESS_TOKEN`은 운영자의 배포용입니다. 뒤의 두 키를 웹 빌드에 포함하지 않습니다.

## 저장과 장기 기억의 의미

클라우드 DB는 수신한 최종 전사문을 보존합니다. 브라우저는 먼저 IndexedDB에 원자적으로 저장하고, DB 확인 후에만 대기열을 제거합니다. 네트워크 단절·재접속·중복 전송에서 복구하도록 설계했습니다. 아직 전사되지 않은 음성이나 OS가 이벤트 수신 전에 종료한 구간까지 복원한다고 보장하지 않습니다. 원본 녹음 파일은 보관하지 않습니다.

원문과 분석을 세션별로 보관하며, 오래된 관련 기록까지 전체 이력의 전문 검색으로 찾습니다. 모든 원문을 매 호출마다 모델에 넣는 방식이 아니며, 모델의 무한 기억을 뜻하지 않습니다. 검색은 키워드 기반으로 임베딩 의미검색은 아닙니다. 최신 기록과 관련 기록 최대12건을 조합하고 실제 교정·복습 표현을 다음 통화에 전달합니다. 모델 출력의 인용 ID와 원문 인용을 서버에서 검증합니다. 인용 존재 검증이 모든 해석의 정확성까지 보장하지는 않습니다.

마지막 발화의 전사·저장을 확인하지 못하면 완료나 분석 성공으로 표시하지 않습니다. 미완료 통화는 이력에서 수신된 기록으로 종료할 수 있습니다. 늦게 복구된 발화가 추가되면 원문 해시가 바뀌어 기존 분석 캐시를 재사용하지 않습니다.

최근 30회는 화면에 표시하고 전체 기록은 페이지를 나눠 내보냅니다. 백업 복원은 회차·발화 원문을 복구하며, 분석은 다시 생성합니다. 복원 배치는 개별 원자적이므로 중간 실패 시 앞선 배치는 남고 재시도할 수 있습니다.

## 컨텍스트와 기억의 용량 관리

과거 원문은 DB에 유지하고, 매 통화에는 검색된 요약·교정·복습 표현 최대 12건과 사실 프로필을 합쳐 16,000바이트 이하로 전달합니다. 사실 프로필은 이름·직업·지역·학습 목표·관심사·대화 선호의 최대 6개 항목입니다. 사용자 원문 인용과 발화 ID를 검증한 통화 분석에서만 추출하고, 검색에 선택되지 않은 오래된 회차도 포함해 실제 발화 날짜가 가장 최신인 값을 사용합니다. 명시적인 잊기 요청은 해당 항목의 빈 값으로 기록해 이전 값이 다시 선택되지 않도록 합니다. 이는 통화 중 즉시 삭제 기능이나 원문 삭제를 뜻하지 않습니다. 역할극 인물 설정과 민감정보는 추출하지 않도록 지시하며, 사실 해석의 정확성까지 자동으로 보장하지는 않습니다. 기존 분석은 재분석할 때부터 사실 항목이 생성됩니다.

실시간 세션은 자동 컨텍스트 잘라내기를 비활성화합니다. 완료된 응답의 입력 사용량이 18,000토큰 이상이거나 마지막 정리 후 10분이 지나면, 조용한 턴 경계에서 잠시 마이크 입력을 멈추고 저장을 확인합니다. 서버가 새 발화와 이전 요약을 바탕으로 다음 요약을 만들고, Realtime이 새 지침을 반영했다고 확인한 뒤 최근 6개를 제외한 이전 대화 항목을 제거합니다. DB 전사문은 제거하지 않습니다. 요약 생성·반영에 실패하면 실시간 항목을 유지하고 입력을 복구하며, 두 번 연속 실패하면 정상 저장·종료 절차를 수행합니다. 공급자 세션 시간 제한에 앞서 50분에 통화를 저장·종료하므로 새 통화로 이어가야 합니다. 무제한 연속 통화나 요약의 완전한 기억 보존을 보장하지 않습니다.

분석은 요청당 원문·메타데이터 60,000바이트 이하로 나누며 최대 8개 부분, 발화 이벤트 12,000개, 주간 회차 500개까지 처리합니다. 개별 발화와 인용은 쪼개지 않습니다. 각 부분을 원문으로 검증한 뒤 결과를 순환 선택해 통합하고, 부분별 범위를 나타내는 요약과 전체 출처를 저장합니다. 서로 다른 부분을 비교한 새로운 추론을 별도 모델로 생성하지 않습니다. 요청 한 번에는 새 부분 최대 2개만 생성하고, 완료한 부분은 저장해 브라우저가 이어서 요청할 때 재사용합니다. 정상적인 이어 처리에는 부모 분석 요청 예산을 중복 차감하지 않습니다. 부분 분석과 통화 중 기억 정리는 기존 일일 voice 요청 예산 30회를 공유합니다. 상한을 넘는 데이터나 한 개만으로 너무 큰 발화는 일부만 분석하지 않고 명시적으로 거절합니다.

## 운영 완료 조건

- 실제 계정의 OTP 로그인, 허용되지 않은 계정 거부 확인.
- 실제 음성 통화와 전사·교정·재접속 이력 복원.
- 브라우저 종료/네트워크 단절 후 대기열 복구, 오래된 기록 검색.
- 다른 계정의 원문·분석 접근 차단을 실제 배포에서도 확인.
- **관리형 DB의 자동 백업과 보관 기간을 설정하고 별도 테스트 대상으로 복원 검증**. 제공자의 요금제·백업 지원에 따라 달라집니다. 무료 프로젝트를 생성한 것만으로 재해 복구가 보장되지는 않습니다.
- 공개 웹 URL에서 휴대폰·PC 마이크 권한, WebRTC, 새 방문자 가입 및 기존 계정의 이력 복원 확인.

현재 이 운영 완료 조건은 모두 통과했다고 보고하지 않습니다. [운영 설정 확인](https://github.com/chungchung234/English/actions/runs/42625210524)에서 아래 남은 항목을 확인했습니다.

- 사용자 지정 SMTP가 없습니다. 임시 테스트 계정은 관리 API로 확인 처리했으므로 실제 가입 메일 전달을 검증한 것이 아닙니다. [Supabase SMTP 설정](https://supabase.com/dashboard/project/domkmxmwmihcfadophfg/auth/smtp)에서 발송 서비스를 연결하고 프로젝트 팀 외 계정으로 로그인 코드 전달을 확인해야 합니다.
- 제공자 메타데이터 기준 보관된 DB 백업0개, PITR 비활성입니다. 자동 백업 정책 설정과 실제 복구 검증이 남았습니다. 요금제 변경이 필요하면 운영자가 선택해야 하며 자동으로 유료 전환하지 않습니다.

`ENGLISH_API_KEY`는 초기 클라우드 연결용으로 선언한 과거 항목이며 현재 앱·배포 코드에서 사용하지 않습니다. 실제 AI 키는 Supabase 함수의 `OPENAI_API_KEY`, 배포 권한은 GitHub Repository secret의 `SUPABASE_ACCESS_TOKEN`입니다.

## 비용과 데이터

사용자당 UTC 일일 요청 제한은 음성30/통화교정20/주간분석3입니다. 동일 원문 재요청은 결과를 재사용합니다. 음성 응답은512토큰으로 제한합니다. 분할 분석 부분과 통화 중 기억 정리도 음성 요청 예산을 공유합니다. 이는 금액 상한이 아니며 OpenAI 프로젝트 사용량·예산 알림도 설정해야 합니다. API 오류·토큰·원문을 서버 로그에 출력하지 않습니다. 사용자의 원음은 음성 처리를 위해 OpenAI로 전송되고, 전사문은 피드백을 위해 전송됩니다. 공용 기기에서는 브라우저에 남는 세션·복구 대기열을 유의하세요.
