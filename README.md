# 시시콜콜 — 링크로 시작하는 영어 통화

모바일 브라우저에서 링크로 접속하는 가벼운 영어 말하기 서비스입니다. 이메일 로그인, 자연스러운 영어 통화, 대화 자동 저장, 개인별 장기 이력, 통화·주간 분석을 제공합니다. 특정 AI 채팅 앱 설치나 사용자별 API 설정은 필요하지 않습니다. 정적 웹 호스팅과 관리형 Supabase를 사용하므로 상시 서버를 직접 운영하지 않습니다.

**현재 상태:** [서비스 링크](https://chungchung234.github.io/English/)에서 로그인 화면에 접근할 수 있으며, 보호된 데이터·AI 기능은 승인된 계정만 이용합니다. 승인된 캐릭터·단계별 모션과 [연구·디자인 결정](docs/design/research-and-decisions.md)을 유지하고, 플랫 발신 버튼의 통화 홈에 이어 최근 통화·복습 개선과 통화 후 표현 연습·이어보기까지 배포했습니다. [최신 배포 검사](https://github.com/chungchung234/English/actions/runs/42764206676)에서 빌드·모바일 검사가 통과했으며 [최근 통화·복습 게시 화면과 검증 범위](docs/design/tabs-refinement/README.md), [통화 홈·글래스 검수](docs/design/call-glass/README.md)를 기록했습니다. [이전 캐릭터 배포 기록](docs/design/research-and-decisions.md#배포와-검증-기록)도 보존합니다.

[이전 공개 모드 검증](https://github.com/chungchung234/English/actions/runs/42639444223)에서는 세 캐릭터의 실제 WebRTC·전사·응답·기억 분리가 통과했습니다. 이는 현재 승인 계정의 실제 기기 재검증과는 별도 기록입니다. 현재의 비승인 테스트 계정은 접근 차단을 확인하며, 검증 목적으로 승인 목록을 바꾸지 않습니다. 이메일 전달과 DB 재해 복구는 아래 운영 과제로 남습니다.

Google·카카오 로그인과 기존 계정 연결 코드를 [배포](https://github.com/chungchung234/English/actions/runs/42743788796)했습니다. Google의 리디렉션 주소 불일치와 실제 소유자 Google 계정의 승인 누락을 수정했습니다. 카카오는 필요한 이메일만 요청하도록 정리했으며, 앞선 `KOE010` 시크릿 불일치 진단은 관리 API 조회값을 잘못 재사용한 검사여서 철회했습니다. [게시된 카카오 요청 검사](docs/auth/kakao-email-scope-verification.json)와 [최신 진단·설정값](docs/social-login-setup.md)을 참고하세요. 페이지 도달과 최종 앱 로그인 성공을 구분해 검증합니다.

## 구성

- `dist/index.html` + `dist/assets/`: 300KB 미만 HTML에 CSS·작은 아이콘을 포함하고, 앱·공식 인증 SDK와 세 캐릭터 이미지는 콘텐츠 해시가 있는 별도 파일로 제공합니다. 캐릭터는 합계 약1.47MB의 무손실 WebP입니다. 방문자에게 연결 설정을 요구하지 않으며 운영자가 빌드 시 공개 연결 정보를 한 번 설정합니다.
- `web/`: 모바일 통화 홈·실시간 통화 화면, 통화·최근 통화·복습 탭, 이메일 코드 로그인, WebRTC 통화, 피드백, 전체 JSON 백업/복원.
- `src/outbox.js`: IndexedDB 복구 대기열. 클라우드 확인 전 삭제하지 않으며 동일 UUID로 재전송.
- `src/auth-session.mjs`: 공식 SDK를 사용한 PKCE 소셜 인증, 세션 유지, 기존 사용자 ID를 보존하는 계정 연결. 브라우저에 개발자 시크릿을 포함하지 않습니다.
- `supabase/migrations/`: 사용자별 RLS, 원문 전사, 분석 출처, 중복 방지, 비용 요청 예산, 전체 이력 검색.
- `supabase/functions/coach/`: 인증·허용 이메일·출처 검사, 음성 API 연결, 분석, 기억 검색. 비밀 API 키는 이 함수에서만 사용.

## 모바일 디자인과 대화 상대

앱 이름과 이미지 로고는 모두 **시시콜콜**입니다. 승인된 블루·네이비 컬러 시스템을 사용하고, 상대 선택·설정·하단 내비게이션에 공통 반투명 글래스를 적용했습니다. 발신 버튼은 그림자 없는 단색 녹색을 유지합니다. `liquid-glass` 스킬의 원칙을 웹의 `backdrop-filter`와 접근 가능한 HTML 컨트롤에 맞게 적용했습니다. 사람 얼굴과 이모지 대신 성격에 따른 색·윤곽·내부 흐름을 가진 AI 형상을 사용합니다.

| 상대 | 성격 | 색·형태 | 음성 |
| --- | --- | --- | --- |
| Alex | 차분하고 실용적인 따뜻함 | 블루·인디고 / 균형 잡힌 구형 / 정돈된 흐름 | `cedar` |
| Mia | 다정하고 사려 깊음 | 라벤더·따뜻한 빛 / 넓고 부드러운 윤곽 / 감싸는 물결 | `marin` |
| Juno | 세심한 경쾌함과 호기심 | 아쿠아·블루 / 비대칭 윤곽 / 유연한 방향 전환 | `verse` |

실제 음성 강약과 듣기·생각·말하기 상태를 따로 읽어 반응합니다. 대기에서는 약10~14초 주기로 천천히 호흡하고 일렁이며, 듣기에서는 세로로 작게 열리며, 생각에서는 수렴하고, 말하기에서는 출력 음성에 맞춰 늘어나고 기울어집니다. 동작 줄이기 설정에서는 같은 캐릭터의 정지 이미지를 표시합니다. WebGL 미지원 환경에서도 작은 CSS 호흡 움직임을 유지하며, 동작 줄이기 설정을 따릅니다.

- [연구 자료와 최종 결정](docs/design/research-and-decisions.md): 출처 신뢰도, 채택/제외 기준, 캐릭터와 모션의 연결, 검증 한계.
- [컬러·렌더링 구현 규칙](docs/design/color-system.md): 토큰, 자산, 상태/음성 신호, 접근성·성능.
- [시각 검증 보고서](design-qa.md): 승인 시안과 브라우저 렌더링 비교.
- [승인된 캐릭터](docs/design/approved-characters/reference.png), [단계별 비교 영상](docs/design/approved-characters/stage-comparison.mp4): 영상은 합성 오디오 강약으로 비교한 시연입니다.
- [대화 성격 연구](docs/persona-research.md): 대화 모델 연구에 근거한 행동 기준. 형상으로 감정을 추정하거나 학습 효과를 보장하지 않습니다.

상대별로 대화·기억 검색·피드백·주간 분석의 맥락을 분리합니다. 목소리와 성격은 서버에서 저장된 회차의 상대를 확인해 선택합니다. 기존 기록은 Alex에 이어집니다. 전체 백업은 세 상대의 기록을 모두 포함하며 복원 시 상대 구분도 보존합니다. 실제 공개 배포 검증은 세 상대 각각의 음성 통화·자동 저장·새로고침·기억 분리를 검사합니다.

## 모바일 전화 UI

상단에서 Alex/Juno/Mia를 선택하거나 메인 화면을 좌우로 밀어 상대를 바꾼 뒤, 중앙 구체와 성격 한 줄을 확인하고 ‘통화’를 누릅니다. 이름은 선택 바에 한 번만 표시하며 검색·큰 연락처 제목·사람 모양 아이콘·통화 전 제한 안내를 제거했습니다. 선택 바에는 내부 구분선이 없고 선택 캡슐이 움직입니다. 상대 선택만으로 통화가 시작되지 않습니다.

최근 통화는 세 상대의 기록을 간결한 목록으로 표시하고, 행을 누르면 피드백·대화문·기억 관리가 있는 상세 화면을 엽니다. 다시 걸기는 목록에서 바로 실행합니다. 복습에서는 교정 문장과 연습 표현을 먼저 보여주고 요약·부가 분석은 펼쳐 봅니다. 주간 분석은 선택한 상대의 최근 7일 내 종료 통화가 있을 때 제공하며 결과를 복습에 표시합니다. 기억 관리는 내 계정 또는 최근 통화에서도 엽니다.

즐겨찾기·주제 선택·더보기·쉽게는 제거했습니다. 새 통화는 자유로운 일상 대화로 시작하며, 과거 회차의 주제는 이력 메타데이터로 남습니다. 통화 조작은 음소거·힌트·대화문 보기·종료입니다. 힌트는 다음에 말할 짧은 영어 예시를 요청하고, AI가 응답 중일 때는 중복 요청을 막습니다.

시간은 최초 음성 연결부터 측정해 경과 시간을 표시하고, 남은 시간은 마지막 1분에만 표시합니다. 같은 통화의 연결 복구나 기억 정리는 50분 종료 시각을 연장하지 않습니다. 일시 끊김 후 음성 분석기를 다시 연결하고, 최종 실패·수동 종료·50분 종료는 마지막 전사를 확인하는 같은 저장 절차를 사용합니다.

승인된 세 AI 형상과 모션을 유지했습니다. 원본 PNG는 보존하고 RGBA 픽셀이 동일한 무손실 WebP를 배포에 사용합니다. 큰 이미지가 HTML에 포함되지 않으며, 비로그인/가려진 화면에서 불필요하게 읽거나 계속 그리지 않습니다. 해시 URL의 별도 파일은 정적 호스트의 캐시 정책에 따라 재사용합니다.

[최신 통화 홈 검증](docs/design/call-glass/README.md), [이전 연락처형 구현 계획](docs/design/phone-ui-implementation-plan.md)과 [이전 모바일 검증 기록](docs/design/phone-ui-qa.md)을 참고하세요. 실제 iPhone Safari의 음성·네트워크 복구 검증과 모의 업스트림 브라우저 검사는 구분합니다.

## 통화 이후 복습

저장 확인 후에는 분석을 기다리는 동안 다른 탭을 사용할 수 있습니다. 표현 하나를 보고 말하거나 가려 말한 뒤 나중에 하기·직접 연습함을 계정에 저장합니다. 다음 통화 주제는 준비만 하며 실제 연결은 통화 버튼으로 시작합니다. [통화 이후 흐름과 구현 범위](docs/post-call-flow.md)를 참고하세요.

최종 배포 디자인의 기존 펼침 영역 안에서 추천·보관함·표현 관리를 제공합니다. 수행·제외·품질 보류 선택은 기기 대기열과 서버 버전으로 관리하고 서버 확인 후 완료로 표시합니다. 기존 `learning_items`와 API를 유지하면서 마이그레이션 `202611100012`의 `learning_state_items`로 학습 상태를 통합합니다. v2 백업은 수행·제외·보류·부분 기록과 기존 기억 설정을 포함하며 v1 복원도 지원합니다. [기획 기준선](docs/post-call-plan.md), [인수 검증](docs/post-call-validation.md), [운영 점검과 남은 과제](docs/production-readiness-20261110.md)를 참고하세요.

고도화에는 의도 보충 후 교정 재검토·명시적 제안 수락, 선택형1·3·7일 지연 회상, 실제 발화의 표현 관찰과 자기 확인, 요청형 주간 목표의 선택·다음 통화·회상 연결을 추가했습니다. 원문과 추가 설명은 분리하며 자동 숙달 판정은 제공하지 않습니다. [구현과 검증 범위](docs/post-call-enhancement-validation.md), [실제 평가 절차](docs/enhancement-evaluation-protocol.md)를 참고하세요. 참여자·사람의 품질 검토·장기 효과 자료는 아직 없습니다.

## 모델 티어링

| 기능 | 기본 모델 | 호출 시점 |
| --- | --- | --- |
| 음성 대화 | `gpt-realtime-2.1-mini` | 통화 중 |
| 음성 전사 | `gpt-realtime-whisper` | 사용자 발화 |
| 검색 임베딩 | `text-embedding-3-small` · 512차원 | 검색할 이력이 있는 비어 있지 않은 질의, 캐시 재사용 |
| 통화 중 기억 정리 | `gpt-6-luna` | 컨텍스트 정리가 필요할 때 |
| 다음 통화용 대화 기억 | `gpt-6-luna` | 저장 후 별도 준비, 앱 재접속 시 미완료 복구 |
| 기억 편집·잊기·순위 결합 | SQL/코드 | 생성 모델 호출 없음 |
| 통화 후 교정 | `gpt-6-luna` | 저장 후 회차당, 동일 원문은 재사용 |
| 최근 7일 분석 | `gpt-6.1-sol` | 사용자가 요청할 때만, 동일 원문은 재사용 |

음성·교정·분석 모델은 `VOICE_MODEL`, `COACH_MODEL`, `ANALYSIS_MODEL`로 바꿀 수 있습니다. 통화 요약은 `CHECKPOINT_MODEL`, 검색은 `EMBEDDING_MODEL`로 분리하며 임베딩 차원은 512로 고정합니다. 상위 모델로 자동 승격하는 재시도는 하지 않습니다. 계정별 실제 모델 접근과 음성 품질은 실연결로 검증해야 합니다. 모델 티어링은 호출 정책이며 실제 절감액을 측정한 결과가 아닙니다. ChatGPT/Claude 구독과 API 과금은 별도입니다.

## 로컬 개발과 검증

Node.js 24, Python3이 필요합니다. 개발 의존성은 lockfile로 고정합니다.

```sh
npm ci --cache /workspace/.npm-cache
npm run check
npm test
npm run test:browser
npm run test:presence
npm run eval:memory
npm run build
```

브라우저 테스트는 Chromium을 사용합니다. `/usr/bin/chromium`이 아닌 경우 `CHROMIUM_PATH`를 지정하세요. 브라우저 테스트의 음성·외부 API 응답은 모의 값이며 실제 음성 연결을 검증하지 않습니다. DB 테스트는 PGlite PostgreSQL 엔진에서 실제 SQL·RLS·복원·분석 경계를 검사합니다.

`npm run dev`는 내부 개발 검증용 정적 파일 서버입니다. 운영 때 이 서버를 실행할 필요는 없습니다. 각 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하고 별도 Git worktree를 만들지 않습니다.

3. **Authentication → Email**에서 이메일 OTP를 켜고 이메일 템플릿에 `{{ .Token }}` 코드가 표시되게 설정합니다. 실제 메일 전달·코드 로그인은 직접 검증해야 합니다. 공개 사용자 가입을 위해 운영용 SMTP를 구성하고 운영자 외 이메일로 코드가 전달되는지 검증해야 합니다. 기본 이메일 발송만으로 모든 방문자에게 전달된다고 가정하지 않습니다.
4. **Edge Functions → Secrets**에서 아래 항목을 저장합니다.
   - `OPENAI_API_KEY`: 실제 OpenAI API 키. 여기에 직접 안전하게 입력합니다.
   - `ACCESS_MODE=public`: 기본값. 누구나 이메일을 인증해 가입할 수 있습니다. 초대제로 운영할 때만 `ACCESS_MODE=invite`와 `ALLOWED_EMAILS`를 설정합니다.
   - `ALLOWED_ORIGINS`: 배포한 웹사이트의 정확한 origin. GitHub Pages 기본 도메인을 사용한다면 `https://chungchung234.github.io`입니다. 경로나 마지막 `/` 없이 입력합니다.
   - 선택: `VOICE_MODEL`, `COACH_MODEL`, `ANALYSIS_MODEL`.
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 Supabase 런타임 기본 바인딩을 사용합니다. 브라우저에 노출하지 않습니다.
5. 관리 토큰은 https://supabase.com/dashboard/account/tokens 에서 발급하고, 채팅 대신 클라우드의 `SUPABASE_ACCESS_TOKEN` 보안 항목에 저장합니다. 프로젝트와 DB 쓰기, 함수 배포 권한이 필요합니다. Supabase CLI 3 기준 `database_write`, `edge_functions_write`, `projects_read` 등 작업에 필요한 범위만 부여하세요.
6. `SUPABASE_PROJECT_REF=domkmxmwmihcfadophfg` 환경 설정을 적용한 후 배포합니다.

```sh
python3 scripts/deploy.py
python3 scripts/deploy.py --apply
```

첫 명령은 권한·연결을 검증하지 않는 로컬 필수 변수 검사입니다. 두 번째 명령은 HTTPS Management API로 원자적 DB 마이그레이션을 적용하고 고정된 CLI로 함수를 배포합니다. DB 포트나 로컬 Docker 서비스는 필요하지 않습니다. 관리 API 배포는 GitHub Actions에서 실제 프로젝트로 검증했습니다. 같은 마이그레이션은 체크섬으로 재적용을 막습니다.

`verify_jwt=false`는 최신 publishable 키와의 게이트웨이 호환을 위한 설정입니다. 함수 자체는 모든 요청의 실제 사용자 JWT를 Supabase Auth에서 검증하고, 이메일 인증과 정확한 origin을 검사합니다. 초대 모드에서만 이메일 allowlist도 검사합니다. 인증 없는 AI 호출을 허용하지 않습니다.

## 공개 웹 배포 (운영자만 한 번 설정)

기존 저장소의 GitHub Pages를 기본 정적 호스팅으로 사용합니다. 다른 정적 호스트에도 `dist/`를 그대로 올릴 수 있습니다.

1. 저장소 **Settings → Secrets and variables → Actions**에 연결 설정을 저장합니다. `SUPABASE_ACCESS_TOKEN`을 Repository secret으로 저장하면 CI가 공개 키 조회와 Supabase 백엔드 배포를 진행합니다. OpenAI 키는 기존 Supabase 보안 설정을 그대로 사용합니다. 아래 공개 변수를 직접 설정하는 방법도 지원합니다.
   - `PUBLIC_SUPABASE_URL=https://domkmxmwmihcfadophfg.supabase.co`
   - `PUBLIC_SUPABASE_KEY`: Supabase의 publishable 또는 anon 공개 키. OpenAI 키나 service_role 키를 넣지 않습니다. 빌드가 비밀 키를 거부합니다.
2. 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 지정합니다.
3. 소스를 `main`에 반영하면 `.github/workflows/pages.yml`이 공개 연결 정보를 포함한 정적 페이지를 빌드·게시합니다. 소스는 `main`에 반영됐습니다. Pages 자동 활성화도 시도하며 저장소 권한이 부족하면 위 설정을 직접 지정해야 합니다. 첫 실제 CI 실행은 공개 연결 정보 누락으로 빌드 단계에서 중단됐으며, 이후 CI는 Repository secret/variable 양쪽을 지원합니다.
4. Actions 배포 결과에 표시된 실제 URL에서 이메일 로그인과 마이크 허용을 검증합니다. HTTPS가 필요합니다.

직접 빌드하려면 같은 `PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_KEY` 환경 변수를 설정한 뒤 실행합니다.

```sh
npm run build -- --require-config
```

빌드는 앱과 공식 인증 SDK를 `dist/assets/app.<해시>.js`에 묶고 SRI와 CSP 해시로 검증합니다. CSS는 HTML에 포함하고 캐릭터 이미지는 별도 해시 파일로 분리하므로 배포할 때 `dist/` 전체를 게시합니다. 방문자는 API 설정 화면 없이 로그인부터 시작합니다. Supabase 관리 토큰이 있으면 공개 키는 관리 API에서 자동 조회하며 브라우저에 관리 토큰을 포함하지 않습니다. 연결 정보 없이 로컬 빌드를 하면 ‘서비스 준비 중’ 화면이며, CI의 `--require-config`는 설정 누락 시 게시를 중단합니다.

세 키는 용도가 다릅니다: Supabase publishable 키는 공개 앱 연결용, `OPENAI_API_KEY`는 서버의 AI 호출용, `SUPABASE_ACCESS_TOKEN`은 운영자의 배포용입니다. 뒤의 두 키를 웹 빌드에 포함하지 않습니다.

## 저장과 장기 기억의 의미

클라우드 DB는 수신한 최종 전사문을 보존합니다. 브라우저는 먼저 IndexedDB에 원자적으로 저장하고, DB 확인 후에만 대기열을 제거합니다. 네트워크 단절·재접속·중복 전송에서 복구하도록 설계했습니다. 아직 전사되지 않은 음성이나 OS가 이벤트 수신 전에 종료한 구간까지 복원한다고 보장하지 않습니다. 원본 녹음 파일은 보관하지 않습니다.

원문과 분석을 세션별로 보관하며, 대화 이어가기용 기억은 학습 노트와 독립적으로 생성·저장합니다. 통화 전체에서 사건·계획·진행 상태·후속 대화 단서를 최대 3개 고르고 짧은 사용자 원문 구절을 근거로 붙입니다. 다음 통화는 직전의 유효한 기억을 우선 받고, 다른 과거 대화 기억은 키워드·최근성으로 최대 4개를 고릅니다. 기존 학습 분석의 검색은 키워드·임베딩 순위를 결합하며 임베딩 실패 시 키워드·최근성으로 보완합니다. 모든 원문을 매 응답에 넣거나 완전 회상을 보장하는 방식은 아닙니다. 출처 검증이 요약 의미의 정확성까지 입증하지는 않습니다. [대화 기억 구조·재처리 구현과 후속 검토](docs/conversation-memory-and-recovery-20261111.md)를 참고하세요.

마지막 발화의 전사·저장을 확인하지 못하면 완료나 분석 성공으로 표시하지 않습니다. 미완료 통화는 이력에서 수신된 기록으로 종료할 수 있습니다. 늦게 복구된 발화가 추가되면 원문 해시가 바뀌어 기존 분석 캐시를 재사용하지 않습니다.

최근 30회는 화면에 표시하고 전체 기록은 페이지를 나눠 내보냅니다. 백업 복원은 회차·발화 원문을 복구하며, 분석은 다시 생성합니다. 복원 배치는 개별 원자적이므로 중간 실패 시 앞선 배치는 남고 재시도할 수 있습니다.

## 컨텍스트와 기억의 용량 관리

과거 원문은 DB에 유지합니다. 독립 대화 기억은 저장 전 최대 2,800바이트, 원문 구절은 기억당 180자이며 직전·과거 대화 기억의 전달 묶음은 최대 6,500바이트입니다. 준비 전에는 짧은 기존 요약 또는 작은 원문 발췌로 보완합니다. 같은 회차의 피드백 문맥은 중복 제거하고, 기존 요약·교정·표현·사실 검색 묶음의 16,000바이트 상한과 최종 데이터 문맥 20,000바이트 상한을 함께 적용합니다. 이 한도는 토큰 사용량이나 비용 절감 실측이 아닙니다. 사실 프로필은 이름·직업·지역·학습 목표·관심사·대화 선호 최대 6개 항목이며 기존 검증된 학습 분석에서 추출합니다. 실제 발화 날짜가 최신인 값을 사용하고 직접 수정·잊기 표시를 우선합니다. 역할극·민감정보는 추출하지 않도록 지시합니다. 통화 중 즉시 원문 삭제 기능은 아니며 사실 해석 정확성은 별도 확인 대상입니다.

대화 기억과 학습 노트는 통화 종료 시 서버 큐에 남고, 앱을 닫아도 예약된 서버 작업자가 이어 처리합니다. 일시 장애·검증 실패는 대기 시간과 총 3회 자동 실패 제한으로 복구하며 완료 결과와 분석 부분 캐시를 재사용합니다. 예산 부족은 다음 UTC 날짜까지 미루고 인증·설정 오류는 자동 반복하지 않습니다. 같은 입력의 수동 요청도 서버의 대기·소진 제한을 공유합니다. 최근 진행 중인 통화에서는 자동 작업 시작을 미룹니다. 기존 앱의 재접속 복구도 유지합니다. [서버 재처리 구조·실행 주기·권한과 검증](docs/post-call-reprocessing-20261111.md)을 참고하세요.

실시간 세션은 자동 컨텍스트 잘라내기를 비활성화합니다. 완료된 응답의 입력 사용량이 18,000토큰 이상이거나 마지막 정리 후 10분이 지나면, 조용한 턴 경계에서 잠시 마이크 입력을 멈추고 저장을 확인합니다. 서버가 새 발화와 이전 요약을 바탕으로 다음 요약을 만들고, Realtime이 새 지침을 반영했다고 확인한 뒤 최근 6개를 제외한 이전 대화 항목을 제거합니다. DB 전사문은 제거하지 않습니다. 요약 생성·반영에 실패하면 실시간 항목을 유지하고 입력을 복구하며, 두 번 연속 실패하면 정상 저장·종료 절차를 수행합니다. 한 번의 통화는 최대 50분이며, 시간에 도달하면 마이크를 멈추고 마지막 전사·저장을 확인한 뒤 종료합니다. 시간이 끝나도 자동으로 다음 통화를 시작하지 않습니다. 무제한 연속 통화나 요약의 완전한 기억 보존을 보장하지 않습니다.

분석은 요청당 원문·메타데이터 60,000바이트 이하로 나누며 최대 8개 부분, 발화 이벤트 12,000개, 주간 회차 500개까지 처리합니다. 개별 발화와 인용은 쪼개지 않습니다. 각 부분을 원문으로 검증한 뒤 결과를 순환 선택해 통합하고, 부분별 범위를 나타내는 요약과 전체 출처를 저장합니다. 서로 다른 부분을 비교한 새로운 추론을 별도 모델로 생성하지 않습니다. 요청 한 번에는 새 부분 최대 2개만 생성하고, 완료한 부분은 저장해 브라우저가 이어서 요청할 때 재사용합니다. 정상적인 이어 처리에는 부모 분석 요청 예산을 중복 차감하지 않습니다. 부분 분석·통화 요약·임베딩에는 각각 독립적인 일일 요청 예산을 적용합니다. 음성 연결 예산을 공유하지 않습니다. 상한을 넘는 데이터나 한 개만으로 너무 큰 발화는 일부만 분석하지 않고 명시적으로 거절합니다.

## 기억 검색과 사용자 제어

기록의 **기억 관리**에서 상대별 사실을 확인·수정·잊을 수 있습니다. 개별 통화는 기억에서 제외하거나 다시 포함할 수 있으며, 원문 기록은 그대로 유지합니다. 진행 중이거나 미완료인 통화가 있으면 먼저 종료해야 기억 정책을 변경할 수 있습니다. 다른 탭의 통화 시작과 정책 변경도 서버의 같은 기억 상태 잠금으로 조정합니다.

수정·잊기 전의 자유 형식 요약에 잘못된 사실이 남아 있을 수 있으므로, 사실을 직접 변경하면 그 시점 이전의 통화 요약을 검색 문맥에서 제외하는 보수적인 방식을 사용합니다. 다른 구조화된 사실은 유지하며 잊기 표시는 모델에게 전달합니다. 이전 기억 버전의 통화 체크포인트는 재사용하지 않습니다. 원문·분석 이력 자체의 삭제 기능은 아닙니다. 회차 교정·주간 분석은 원문을 분석하는 별도 기능이므로 기억 검색 제외와 독립적으로 과거 기록을 표시할 수 있습니다.

**검색 기억 업데이트**는 최대 4개 문서를 한 번에 색인합니다. 최신 분석의 요약·교정·복습 표현만 최대 6KB의 문서로 만들고 모델·차원·문서 해시를 연결합니다. 제외되거나 변경된 분석은 저장 및 조회 시 다시 검사합니다. 모델이 다른 벡터는 비교하지 않습니다. 첫 버전은 사용자·상대별 최신 분석 최대 2,000건에 배열 코사인 검색을 수행하므로 대규모 이력에는 pgvector/HNSW 전환이 필요합니다. 전체 이력이 모두 의미 검색되는 것으로 표시하지 않습니다.

백업에는 기억 수정·제외 정책도 포함합니다. 복원은 회차와 해당 제외 정책을 같은 배치에서 적용하고 현재의 더 엄격한 정책을 유지합니다. 예전 형식의 백업이 지금의 잊기 표시나 제외 설정을 해제하지 않습니다.

[실행 계획과 모델 티어](docs/memory-upgrade-plan.md), [평가 범위와 결과](docs/memory-evaluation.md)를 참고하세요. `npm run eval:memory`는 실제 SQL 엔진과 합성 벡터로 검색·격리·정책 동작을 평가합니다. 실제 임베딩 모델의 언어 의미 이해도나 영어 학습 효과를 측정하는 평가는 아닙니다.

- 실제 계정의 OTP 로그인, 허용되지 않은 계정 거부 확인.
- 실제 음성 통화와 전사·교정·재접속 이력 복원.
- 브라우저 종료/네트워크 단절 후 대기열 복구, 오래된 기록 검색.
- 다른 계정의 원문·분석 접근 차단을 실제 배포에서도 확인.
- **관리형 DB의 자동 백업과 보관 기간을 설정하고 별도 테스트 대상으로 복원 검증**. 제공자의 요금제·백업 지원에 따라 달라집니다. 무료 프로젝트를 생성한 것만으로 재해 복구가 보장되지는 않습니다.
- 공개 웹 URL에서 휴대폰·PC 마이크 권한, WebRTC, 새 방문자 가입 및 기존 계정의 이력 복원 확인.

현재 이 운영 완료 조건은 모두 통과했다고 보고하지 않습니다. [운영 설정 확인](https://github.com/chungchung234/English/actions/runs/42625210524)에서 아래 남은 항목을 확인했습니다.

- 사용자 지정 SMTP는 연결돼 있지만, 2026-11-10 점검에서 잘못된 서버 주소를 수정한 뒤에도 Google의 `535: Username and Password not accepted` 거부를 확인했습니다. [Supabase SMTP 설정](https://supabase.com/dashboard/project/domkmxmwmihcfadophfg/auth/smtp)에서 발송 계정의 앱 비밀번호를 갱신하고 실제 코드 전달·로그인을 확인해야 합니다. [진단과 복구 절차](docs/email-login-recovery.md)를 참고하세요. 임시 테스트 계정의 관리 API 확인 처리는 실제 메일 전달 검증이 아닙니다.
- 제공자 메타데이터 기준 보관된 DB 백업0개, PITR 비활성입니다. 자동 백업 정책 설정과 실제 복구 검증이 남았습니다. 요금제 변경이 필요하면 운영자가 선택해야 하며 자동으로 유료 전환하지 않습니다.

`ENGLISH_API_KEY`는 초기 클라우드 연결용으로 선언한 과거 항목이며 현재 앱·배포 코드에서 사용하지 않습니다. 실제 AI 키는 Supabase 함수의 `OPENAI_API_KEY`, 배포 권한은 GitHub Repository secret의 `SUPABASE_ACCESS_TOKEN`입니다.

## 비용과 데이터

사용자당 UTC 일일 요청 제한은 음성 연결30/통화교정20/의도 재검토10/주간분석3/통화요약60/분할분석80/임베딩200입니다. 임베딩 색인은 요청 한 번에 최대 4개 문서를 처리합니다. 동일 원문 재요청은 결과를 재사용합니다. 음성 응답은512토큰으로 제한합니다. 분할 분석 부분·통화 요약·임베딩은 각각 별도 예산으로 관리합니다. 이는 금액 상한이 아니며 OpenAI 프로젝트 사용량·예산 알림도 설정해야 합니다. API 오류·토큰·원문을 서버 로그에 출력하지 않습니다. 사용자의 원음은 음성 처리를 위해 OpenAI로 전송되고, 전사문은 피드백을 위해 전송됩니다. 공용 기기에서는 브라우저에 남는 세션·복구 대기열을 유의하세요.

모델별 추론·캐시·예산·실측 검증은 [모델과 비용 정책](docs/model-policy.md)을 참고하세요.
