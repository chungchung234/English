# 대화 작성과 검증된 음성 버퍼

기반 소스는 `a4f712e808145742239855edf1add136d6824edf`다. 이 문서는 후속
후보의 구현 계약이다. 배포·기능 검사·실제 생성·실기기 음향 검증은 각각의
증거가 있어야 완료로 기록한다. 현재의 배포 기준과 혼동하지 않는다.

## 바꾸는 이유

같은 캐릭터 자료로 mini·standard 음성 모델과 간결한 지침을 비교했지만
메뉴식 시작과 비슷한 반응 구조가 남았다. [실제 모델 평가](companion-model-evaluation-20261114.md)는
불리한 결과도 보존한다. 지침에 인사 길이·문장 수·질문 비율을 더해 해결하지 않는다.

후보는 캐릭터 대화 내용을 먼저 작성하고, 그 문장에 대한 별도 음성 합성을
검증한 뒤 브라우저가 소유한 PCM 버퍼로 재생한다. 친근한 대화가 통화의 목적이며
학습은 통화 뒤 사용자가 선택한다. 기존 페르소나·관점·근거가 있는 기억과 현재
발화 구분을 보존한다. 작성기가 바뀌어도 교사 역할이나 의무 연습을 추가하지 않는다.

## 요청과 자료의 경계

| 단계 | 신뢰하는 자료와 결과 |
| --- | --- |
| 접속·전사 | 기존 브라우저 마이크와 수동 턴 제어. 브라우저 AEC·소음 억제는 기기 지원 범위에서 유지 |
| 대화 권한 준비 | 서버가 활성 통화·소유자·캐릭터·승인·기억 revision·자료 적격성을 확인한 권한 세대 |
| 내용 작성 | 저장 ACK가 있는 현재 사용자 원문과 적격한 이력만 사용. 시작의 현재 사용자 발화는 없음 |
| 음성 합성 | 서버가 저장한 작성 문장만 입력. 클라이언트가 자유 지침이나 대체 문장을 보내지 않음 |
| PCM 승인 | 원문 digest·버퍼 digest·소유권·형식·단일 정상 완료·보고 전사 단어열을 확인 |
| 재생 기록 | 강한 출력 위치 확인과 단순 추정 종료를 구분. 둘 다 사람이 들었다는 증명은 아님 |

한 응답은 계정 범위·통화·캐릭터·call epoch·turn nonce·turn ID·assistant event ID·
권한 세대·기억 revision·playback epoch에 결속한다. 지연 응답이나 다른 통화의
자료를 화면·재생·기억에 재사용하지 않는다. 취소 전에 작성 예약이 도착하지 않은
경우에도 같은 nonce의 늦은 작업이 다시 살아나지 않아야 한다.

내용·합성의 비용 예약을 각각 기록한다. 네트워크 실패로 실제 생성량을 모르면
0회라고 보고하지 않는다. 자동 재작성·재합성·다른 모델 우회는 하지 않는다.

## 잡음과 실제 끼어들기

기존 경로는 발화 후보가 생기면 제공자의 출력을 취소·비워 원래 말을 복원할 수
없다. 후보 경로는 먼저 로컬 PCM 커서와 리샘플 위상을 보존한 채 멈춘다.

| 결과 | 동작 |
| --- | --- |
| 빈 전사 또는 잡음으로 기각 | 같은 버퍼·커서에서 이어 재생. 새 답변·인사·합성을 만들지 않음 |
| 실제로 채택된 사용자 발화 | 이전 답변을 끝내고 저장된 새 발화로 응답 작성 |
| 전사 실패·판단 미확인 | 자동으로 원래 말을 버리거나 사용자 의도를 추정하지 않고 ‘이어 듣기’·‘답변 멈춤’ 제공 |
| 사용자가 명시적으로 중지 | 버퍼를 끝내고 지연 완료가 와도 재개하지 않음 |
| 기억·계정·통화 권한 변경 | 버퍼와 작성 권한 무효화. 검증된 새 권한을 받기 전에는 재생하지 않음 |

새 최소 발화 길이나 단어 차단 목록을 두지 않는다. 짧은 뜻 있는 발화도 사용자
발화가 될 수 있다. 빈 전사는 실제 발화 없음의 물리적 증명이 아니므로 전사
실패와 구분한다. 브라우저 밖 스피커·방·마이크의 잔향과 이미 기기 출력에 넘어간
짧은 음성 꼬리까지 소프트웨어가 즉시 제거한다고 주장하지 않는다.

## 브라우저 재생과 근거

첫 실제 클릭·Enter·Space에서 AudioContext를 먼저 열고 비동기 준비를 시작한다.
재생 허용이 막히면 동일한 음성을 다시 시도한다. 새 응답을 생성하지 않는다.
Worklet은 24kHz mono signed 16-bit little-endian 원본을 기기의 실제 sample rate로
변환하고, 출력 gain 뒤의 참조 스트림을 기존 로컬 음성 판정에 제공한다.

PCM 전체와 digest가 확인되기 전에는 clip을 재생하지 않는다. 완료는 최종 출력
프레임과 `getOutputTimestamp()` 위치를 대조한다. 확인할 수 없는 기기에서는
`estimated_drain`으로 종료할 수 있지만 공유 기억·채택된 assistant 이력의 근거로
승격하지 않는다. 로컬 출력 위치를 확인한 `played_through`도 client report이며
실제 사람이 듣거나 이해했다는 증거는 아니다.

Worklet은 별도 content hash 파일이다. 주 번들의 SRI와 제한된 CSP가 descriptor와
정확한 Worklet URL을 보호하고 빌드 검사는 실제 바이트 hash를 대조한다.
`audioWorklet.addModule()`에는 SRI 인수가 없으므로 Worklet에 브라우저 SRI를
적용했다고 표현하지 않는다.

## 기억과 긴 통화

기존 원문은 보존한다. 정상 컨텍스트 정리와 개인정보 퇴역은 구분한다. 긴 통화는
적격한 이력을 검증된 checkpoint와 최근 원문으로 정리하며 시간 경과만으로
끊거나 과거 사용자 발화를 임의 삭제하지 않는다. 원문 하나가 평소 창보다 길면
단일 발화를 중간에 잘라 다른 의미로 만들지 않는다.

제공자의 암호화 continuation은 서버 전용·짧은 TTL·같은 권한과 출처·재생 완료된
이력에 한정한다. 브라우저·로그·내보내기로 보내지 않는다. 미재생·취소·잊기·제외·
원문 변경·checkpoint 전환으로 근거가 달라지면 재사용하지 않고 새 적격 문맥으로
작성한다. 기억을 빼고 복구하는 경우도 활성 통화·DB 승인과 새 권한 확인을 거친다.

## 검증과 채택

개발 중 capability는 기본 꺼짐이다. 채택 전에 SQL/RLS·예약/취소 경합·출처 변경·
전사/원문 ACK·재생 근거·Worklet/CSP·기존 경로 회귀를 검사한다. 실제 API 작성→
합성→네이티브 브라우저 출력의 지연도 하나의 고정 합성 사례로 측정한다.

모의 backend·RTC로 확인한 UI 기능, 실제 provider 생성, 네이티브 WebAudio,
실제 마이크·물리적 에코는 서로 다른 증거다. 이 구현이나 작은 합성 표본만으로
친근함·스피커 잡음 문제가 완전히 해결됐다고 보고하지 않는다. 반복 통화의
시작·상호성·관점 일관성·사용자 선호와 실제 기기 음향은 후속 평가 대상이다.
