# 통화 응답·종료 후 대화문 개선

작성일: 2026-11-11 KST (2026-11-10 UTC). 통화 후 대화문 접근, 생각할 시간, 답변 길이, 응답 언어를 함께 개선한다. 기존 화면 디자인·말하기 속도 조절·계정별 저장·E01~E05 학습 상태를 유지한다.

**연구 후 정정:** 이 문서는 최초 구현 기록이다. [후속 근거 검토](research/voice-experience-evidence.md)에서 2초·10~25단어·전사 언어 자동 감지는 효과가 입증된 최적값이 아닌 초기 가설로 분류했다. 512토큰 상한이 긴 답변의 원인이라는 표현은 철회한다. 자동 검사 통과와 실제 대화 품질은 구분한다.

## 문제와 원인

| 사용자 문제 | 코드에서 확인한 구현 요인 | 변경 설계 |
| --- | --- | --- |
| 통화를 끝내고 대화 내역을 바로 보기 어려움 | 종료 처리에서 마지막 전사·전송·서버 종료를 기다린 뒤 복습으로 이동하며 대화문은 최근 통화의 접힌 영역에 있음 | 종료 버튼을 누르면 받은 대화문을 즉시 열고 마지막 전사·저장 확인은 별도 상태로 갱신. 피드백 생성과 대화문 보기를 분리 |

| 한국어 질문에 한국어로 대답함 | 기존 통화 지침이 한국어 도움 요청 시 한국어 설명을 허용함 | 한국어 질문·한국어 설명 요청에도 쉬운 영어로 응답. 한국어 원문을 소리내 반복하지 않음. 입력 전사는 언어 자동 감지 |

## 동작과 경계

- 종료 후 대화문은 수신된 발화부터 보여준다. 늦게 도착한 마지막 전사를 갱신하고, AI·사용자 화자를 구분하며 HTML로 해석하지 않는다.
- ‘지금 볼 수 있는 대화문’과 ‘서버 저장 확인’을 구분한다. 미전사·오프라인·저장 실패를 완료로 표시하지 않는다. 빈 통화에는 빈 상태를 표시하고 다른 통화의 내용을 섞지 않는다.
- 통화 종료 후 마이크와 재생을 멈추고 마지막 전사를 받을 연결만 짧게 유지한다. 계정·대화 상대·회차가 바뀌면 이전 비동기 결과를 노출하지 않는다.
- 기본 음성 설정은 `server_vad`, `threshold=0.5`, `prefix_padding_ms=300`, `silence_duration_ms=2000`, `create_response=true`, `interrupt_response=true`다. 2초는 서버가 감지한 무음을 기준으로 하며 네트워크·생성 지연은 별도다. 사용자가 다시 말하면 무음 판정이 이어지지 않으며, AI가 말하는 중에도 사용자가 끼어들 수 있다.
- 의미 기반 턴 감지는 문장이 끝났다고 판단하면 빠르게 응답할 수 있어 이번에는 예측 가능한 무음 시간을 선택했다. 대기 중 자동 재촉용 idle timeout은 추가하지 않는다.
- 첫 인사와 통화 중 기억 갱신에도 동일한 영어·간결 규칙을 사용한다. 힌트는 실제 공급자 세션 지침을 받은 뒤 제공하며 최신 기억·개인정보 경계를 포함해 요청한다.
- 통화를 끝낸 직후에는 대화문을 위에 펼쳐 둔다. 사용자가 최근 통화에서 피드백을 명시적으로 선택하면 피드백을 먼저 보여주고 대화문은 아래에서 펼칠 수 있게 한다. 최근 통화 상세를 열면 그 통화의 대화문은 바로 펼친다.
- 영어 응답은 음성 통화에 적용한다. 한국어 UI와 통화 후 피드백의 한국어 설명은 유지한다. 원본 전사에서 한국어를 지우거나 영어로 대체하지 않는다.
- 한국어 발화 자체를 영어 문법 오류로 분류하지 않도록 피드백 지침도 보완했다. 요청·문맥이 뒷받침하는 한국어→영어 표현 제안은 선택형 대안으로 다루고, 원문 인용은 원래 언어 그대로 유지한다. 피드백 요청의 캐시 버전을 구분하며 기존 임베딩 캐시는 유지한다.
- 출력 토큰에는 음성 생성도 포함되므로 짧은 문장까지 끊길 수 있는 낮은 상한으로 줄이지 않는다. 기존512토큰 상한을 유지하고 짧은 응답은 지침으로 유도하며 재생·전사를 임의 절단하지 않는다. 정확한 단어·문장 수와 실제 발화 품질은 실제 통화에서 확인해야 한다.

## 검증·배포 기록

공급자 요청 경계에서 VAD·토큰 상한·언어 설정·인사·기억 갱신 지침을 검사한다. 실제 Chromium에서는 종료 직후 대화문, 늦은 전사, 저장 중·실패·빈 상태, 새로고침 후 복원, 힌트의 지침 보존을 확인한다. 외부 인증·모델·WebRTC는 자동 검증의 명시적인 테스트 응답이며 실제 사용자의 응답 길이·체감 대기 품질과 구분한다.

로컬 최종 단위 검사173개와 구문·Deno 타입 검사가 통과했다. 기존 브라우저17개·통화 후16개·고도화6개·캐릭터/오디오5개와 새 대화문6개, 총50개 그룹으로 확인한다. 새 그룹은 서버 저장을 의도적으로 지연한 상태의 즉시 표시, 늦은 전사·피드백 실패, 재접속·최근 통화, 빈 통화, 부분 전사·명시적 복구, 기기 저장 실패를 다룬다. 작은 화면의 스크린샷도 확인했다.

최종 배포 결과는 해당 변경 PR과 CI에 기록한다. DB 스키마 변경과 API 키 교체는 필요하지 않다. 실제 사용자의 체감 대기와 답변 길이·응답 언어는 자동 검증 통과와 구분한다.
