# 통화 중 문맥 정리와 오류 처리 개선

기준 소스는 `d41b871`이며, 공개 배포 식별자 `git:d998452baac429fbff5f4fdd7eac03a046402a96`와 관련 코드가 같은 것을 확인했다. 검수 중 원격에 반영된 `1eb405d`의 50분 통화 제한 변경을 병합했고, 10분 고정 정리 제거와 용량 기반 보호는 그대로 유지한다. 이전 작업의 마지막 통화 상대 복원 변경도 보존했다. 검증 환경은 Node 24, 관리형 Linux의 Chromium, 390×844 및 320×568이다.

## 문제와 변경

약 10분 뒤 자동 요약·항목 삭제의 개별 Realtime 오류를 음성 연결 장애와 전사 실패로 함께 처리했다. RTC와 마이크가 정상이어도 종료 안내가 남고, 이후 정상 전사를 저장해도 세션 완료 처리가 막혔다.

- 10분 경과 조건을 제거했다. 완료된 응답의 입력 사용량이 18,000토큰 이상이거나 실제 문맥 한도 오류가 있을 때만 정리한다. 실제 한도 오류의 복구는 일반 유지보수의 60초 재시도 간격을 우회한다.
- 새 지침 반영과 개별 항목 삭제는 요청 ID·ACK를 추적한다. 삭제 확인된 항목만 현재 세션 목록에서 제거하고, 일부 실패한 항목은 재시도한다. 동일한 목표 상태를 확인하는 늦은 ACK도 재시도 작업에 반영한다.
- 요청 오류·지연은 진단만 남기고 통화나 전사 성공을 오염시키지 않는다. 실제 ASR 실패·미확인 최종 전사·저장 실패의 부분 기록 처리는 유지한다. 실제 용량 한도에서 문맥 복구마저 실패하는 경우에는 정상 전사·저장 절차로 종료한다.
- `call_diagnostics`에는 오류 코드, 요청 종류, 경과 시간, 연결 상태, 앱 버전만 저장한다. 원문 오류 메시지·전사문·음성·SDP·인증 값은 전달하지 않는다. 본인·승인 계정 검증, 전체 배치 검증, 세션별 200건 한도, 동일 ID 재시도와 명시적 ACK를 적용한다. 진단 실패가 통화 UI나 저장 결과를 바꾸지 않는다.

## 검증 기록

- `npm run check`, 연결 설정을 포함한 `npm run build -- --require-config` 통과.
- `npm test`: 310개 전체 통과. 신규 테이블을 스키마 계약 검사에 반영했다.
- 최종 `test/browser.mjs`, 신규 `test/voice-reliability.browser.mjs`, 통화 전환·전사·응답 제어·시간/기억·복습/학습 확장·저장/별도 학습 노트 등 영향을 받는 브라우저 회귀가 모두 통과했다. 통화 후 경험 fixture에는 종료 전에 committed 수신을 명시하고, 최종 전사의 실제 DB 저장과 재방문 렌더링을 확인해 비동기 타이밍 의존성을 제거했다.
- 운영 DB에 `202611110008_call_diagnostics`를 적용했다. 테이블·RLS·실행 권한을 확인하고, 실제 승인 계정 역할의 진단 저장·본인 조회·ACK를 롤백 트랜잭션에서 검증했다. 검증용 세션/진단은 남기지 않았다.
- 프런트 공개 반영은 릴리스 작업과 공개 번들의 `LOOP_CLIENT_BUILD`를 대조해 별도로 확인한다. 최초 VOC의 원본 provider 오류는 수집되어 있지 않아 특정 오류 코드나 삭제 거절을 실제 발생 원인으로 확정하지 않는다. 과거 미완료 통화를 이 변경만으로 자동 완료 처리하지 않는다.
