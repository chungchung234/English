# 캐릭터 관점과 대화 교환 기억

초기 기준은 `b23bf7b9ff80d73591339b3d5395bc89cea5e1d5`이며, 기존 검수 fixture
정정까지 반영한 기반은 `9caa42bcfde1eec20dd6b5fe4b8f11efebbfa974`다.
웹 연결 복구와 분리해 검증하는 후속 변경이다. 연구 근거와 미검증 가설은
[연구 문서](research/natural-companion-dialogue-20261113.md)에 둔다.
이 문서는 구현 계약이며, 테스트나 배포가 끝났다는 기록을 대신하지 않는다.

## 사용자 경험

통화 중에는 선택한 캐릭터와 자연스럽게 이야기하고, 통화 뒤에 실제 발화를
바탕으로 학습한다. 통화마다 수행할 수업, 인사 길이, 질문 수, 자기 의견의 빈도를
추가하지 않는다. 이미 연결된 순간에는 현재 사용자 발화가 없음을 명시하고,
과거 질문을 방금 받은 말처럼 답하지 않게 현재 입력과 과거 자료를 구분한다.

캐릭터 자신의 관점은 사용자 프로필과 별도로 작성·버전 관리한다.

| 캐릭터 | 관점의 소재 | 관점을 쓰는 방식 |
| --- | --- | --- |
| Mia | 조용한 공간의 디테일, 여운이 있는 책, 일상의 작은 변화 | 무엇을 좋아하는지와 이유, 다른 선택이 어울리는 조건을 함께 제공 |
| Alex | 서로 잘 들리는 공간, 단순한 맛과 즉흥성, 방향을 바꿀 수 있는 산책 | 상황에 맞는 자기 생각을 보탤 수 있는 자료 |
| Juno | 어색하지만 흥미로운 디자인, 익숙한 음악의 예상 밖 소리, 뜻밖의 연결 | 진지한 대답이 필요한 상황도 포함한 유연한 취향 |

이 설정은 실제 인간의 하루나 오프라인 이력을 만들어내는 근거가 아니다.
매번 같은 취향 문장을 읽거나 사용자 의견에 무조건 동의·반대하는 규칙도 아니다.

## 이전에 함께 나눈 말

`conversation-exchange-v1`은 사용자 원문과 캐릭터 원문을 서로 다른 화자로
묶는다. 발화 ID, 출처 통화, 통화 시각·시간대, 기억 revision,
`client_reported_playback_completed`라는 입수 근거를 가진다.
캐릭터 발언은 캐릭터가 그 말을 했다는 근거로만 사용한다. 사용자 사실·동의나
사람이 실제로 소리를 들었다는 증거로 해석하지 않는다.

브라우저는 승인된 사용자 발화와 생성·재생이 끝난 미취소 캐릭터 발화의 ID를
관찰할 때 당시 기억 revision을 동기적으로 고정한다. 양쪽 원문이 서버에
저장됐다는 응답을 받은 뒤 별도 IndexedDB 대기열에 ID와 revision만 보관한다.
원문 저장이나 통화 종료를 이 선택적 전송 때문에 실패시키지 않는다.
새로고침·오프라인 재시도에도 원래 revision과 receipt ID가 유지된다.
예전 생성 원문에 재생 근거를 소급하지 않는다.

서버는 계정·캐릭터·출처 통화 소유권과 승인, 실제 저장된 화자별 원문을
검사한다. 원문과 통화 속성 digest가 바뀌면 기존 receipt로 복원할 수 없다.
현재 revision과 달라진 늦은 receipt는 명시적으로 폐기 응답하고, 원문은 보존한다.
제공자가 출력 버퍼를 비운 사건은 재생 종료와 구분하며, 나중에 종료 사건이
오더라도 지워진 출력을 재생 완료 근거로 승격하지 않는다.

종료·저장 완료된 적격 통화에서 같은 캐릭터의 교환만 검색한다. 상한은
최근 receipt 200개, 출처 통화 2개, 교환 4개, 모델 전달 4,200바이트다.
기존 사용자 handoff에서 고른 발화를 우선하고 짧은 작별 인사가 중요한 이야기를
밀어내지 않게 순위를 정한다. 이 순위는 응답 과제나 다음 질문을 지정하지 않는다.
시작에는 이미 선택된 적합한 최근 이야기의 사용자 인용과 정확히 연결되는
교환만 선택적으로 붙인다. 전체 학습 노트와 교정·연습 지시는 전달하지 않는다.

## 잊기·제외와 통화 복구

검색 단계에서 기존 기억 적격성·제외·보류·삭제 규칙을 그대로 적용한다.
명시적 잊기 시각보다 이전에 시작된 교환은 AI 재진술까지 함께 제외한다.
시각을 모르는 잊기 표식이 있으면 교환을 전달하지 않는다. 원문 근거가 있는
잊기는 별도의 단조 증가 경계에도 남기고 기억 revision을 전진시킨다. 나중에
같은 항목에 새 값을 말하거나 잊기 발화의 원문을 삭제해도 이 경계는 낮아지지
않는다. 경계 뒤에 시작된 새 통화는 다시 교환 근거가 될 수 있다.
준비 중에는 새 목록에서 선택했던 정확한 교환이 여전히 적격인지 최종 확인한다.
선택하지 않은 새 자료가 추가됐다는 이유만으로 실패시키지 않는다.

통화 중 checkpoint가 `MEMORY_CHANGED`, `MEMORY_SOURCE_CHANGED` 또는
`HISTORY_CHANGED`를 받으면 이전 승인 지침을 무효화하고, 사용 완료된 옛 모델
참조를 퇴역시킨다. `voice-context`는 활성 통화 소유권과 현재 DB 승인을 확인해
과거 자료를 조회하지 않는 기억 없는 설정만 반환한다. 브라우저는 8초 예산 안에
정확한 설정 ACK를 받은 뒤 입력을 재개한다. 실패하면 마이크와 옛 지침을 이용한
힌트·응답을 막고 기존 통화 화면에서 ‘대화 다시 연결’을 제공한다.

원문과 재생 근거 장부는 별도로 보존한다. 이후 응답과 checkpoint는 퇴역한
모델 참조를 다시 사용하지 않는다. 정상적인 컨텍스트 정리로 제공자에서만
삭제된 발화는 계속 checkpoint 근거가 될 수 있어 개인정보 퇴역과 구분한다.
구형 자동 응답 경로는 과거 제공자 항목의 삭제 ACK까지 받아야 입력을 재개한다.

## 검증 경계

SQL/RLS·원문 digest·지연 receipt·revision·화자 분리 검사와 브라우저 저장 ACK/
재생 완료/정정 후 복구 검사는 기능 계약을 확인한다. 실제 모델의 지침 반영,
합성 다중 턴 대화 내용, 실기기 음향·체감 친근함은 서로 다른 검증이다.
합성 대화 평가를 실사용자 선호나 실제 마이크 환경의 소음 개선으로 보고하지 않는다.
기존 수동 턴 제어와 AEC/소음 억제를 유지하며, 맞장구와 실제 끼어들기의 의도 구분은
이번 캐릭터 자료 변경만으로 해결됐다고 주장하지 않는다.
