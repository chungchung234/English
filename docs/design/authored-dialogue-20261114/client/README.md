이 기록은 로컬 검수이며 운영 활성화·배포 확인은 별도입니다.

- 기존·새 floor 48개와 독립 작성 대화 helper 30개, 총 78개 검사 통과.
- 실제 HTTP로 제공한 분리 빌드에서 12개 작성 대화 흐름 통과. 루트 전체 브라우저 명령의 21개 스크립트도 통과했으며, 그 로그를 `browser-check.txt`에 보존했습니다. 본문 SRI/CSP와 실제 AudioWorklet 및 VAD WASM을 사용했습니다.
- 초기 수동 정책 ACK 이전에 시계·첫 응답을 시작하지 않습니다. RTC 원격 음성을 재생하지 않고 작성 대화 경로만 사용합니다.
- 발화 후보의 ASR가 비면 같은 버퍼의 source frame·resampler phase에서 이어집니다. ASR 실패는 명시적인 이어 듣기 또는 답변 멈춤을 제공합니다.
- 실제 발화는 기존 버퍼를 취소한 뒤 원문 저장 ACK를 기다려 다음 답변을 요청합니다. 중단한 AI 문장은 승인된 과거 문맥에 들어가지 않습니다.
- ASR의 임시 provider 입력은 최종 ASR와 필요한 원문 저장 ACK 후, 최대 4개의 정확한 삭제 요청으로 비웁니다. 원문·승인 발화·수동 답변 후보는 보존하고 나중 writer 문맥에서 사용할 수 있습니다. 선택적 정리 실패는 통화를 막지 않으며 다음 안전한 ACK에서 재시도합니다.
- 계정 변경은 새로고침 전에 실제 PCM Context를 닫습니다. 페이지 생명주기 전환은 기존 재생과 마이크를 무효화하며 복귀 시 새 권한을 확인하도록 합니다. 실제 SDK의 BroadcastChannel 로그아웃 경로와 native Context.close 호출을 확인했습니다. pagehide/pageshow 검사는 이벤트 wiring 검사이며 실제 BFCache 보존 실험은 아닙니다.
- 잘못된 PCM digest는 재생 전에 거부합니다. 기억 없는 권한 새로고침은 이미 기억 없는 모드에서도 reset:true로 서버 권한을 새로 만들고, 새 인사를 자동 생성하지 않으며 RTC 재접속·음소거로 우회할 수 없습니다.
- 재생 완료 보고의 caller ID는 해당 writer 요청에 실제 사용한 현재·과거 user source에만 묶입니다. 이미 기억 없는 모드에서 다시 reset한 뒤 새 caller·완료 재생을 진행해, 이전 caller ID가 새 보고에서 제외되고 이전 원문은 보존됨을 검증했습니다.
- native output timestamp를 확인한 완료와 추정 drain을 구분합니다. timestamp가 없으면 완료 receipt를 보내지 않습니다.
- BUDGET_EXCEEDED와 COST_BUDGET_EXCEEDED는 통화의 남은 생성·마이크·힌트·재연결을 막고 이용 한도를 안내합니다. 자동 재시도·새 인사·이전 PCM 재생 없이, 늦게 도착한 원문 저장과 정상 종료 ACK는 계속 처리합니다. 저장 오류로 표시하지 않습니다.
- 작성 대화의 이차 재생 watchdog은 준비·전체 버퍼 재생·출력 위치 확인을 포함하도록 180초로 설정했습니다. 별도의 provider/player 제한은 유지하며 문장 길이 규칙을 추가하지 않았습니다.
