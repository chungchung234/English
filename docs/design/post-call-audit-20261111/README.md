# 통화 종료 → 복습 경험 감사와 개선 기획

2026-11-11 · 진단·개선안 · 구현 전 검토 자료

현재 화면은 통화를 마친 사람이 **이번 통화에서 무엇을 가져가고, 지금 무엇을 하면 되는지** 알아내기 어렵다. 열린 대화문, 이전 피드백 목록, 저장·분석 상태와 표현 연습을 같은 화면에 이어 붙여 핵심 결과가 뒤로 밀린다. 새 장식이나 더 많은 설명보다 진입 목적·정보 순서·상태 경계를 먼저 정리할 필요가 있다.

**검토 범위와 증거**

- 대상: 통화 끊기 직후 → 전사/저장 확인 → 피드백 준비/완료 → 표현 연습 → 저장 완료 → 다음 방문. 무발화·전사 누락·기기 저장 실패·분석 실패도 확인했다.
- 현재 공개 서비스의 HTML·CSS·JS·이미지를 변경 없이 다운로드해 원래 CSP와 함께 Chromium에서 렌더링했다. 게시 모듈은 `assets/app.70f6d5b1dfa1.js`. [공개 파일 식별](source-verification.json).
- 인증·음성·분석 응답은 합성 데이터이며 보호 API는 전부 가로채 실제 사용자 계정·기록·모델에 접근하지 않았다. 로컬 PGlite의 실제 SQL/RLS/RPC·IndexedDB를 사용했다. SQL 집합은 현재 저장소 `ee6acbe`의 상위 호환 집합이므로 운영 DB의 전체 동작을 감사한 결과는 아니다.
- 모바일 390×844와 320×568 CSS px, 브라우저 Asia/Seoul. 동일한 앱에서 사용자/AI 합계 12개 발화의 예시 통화와 짧은 기록을 사용했다. 생성 응답을 지연시켜 상태를 관찰했으며 실제 서버 지연 시간을 측정한 것은 아니다.
- 저장소 최신 소스와 공개 모듈이 달라, 최종 증거는 **공개 모듈**로 다시 캡처했다. 이전 감사·대화의 이미지를 근거로 재사용하지 않았다. 공유 브라우저 연결 오류 때문에 자동화 Chromium을 사용했다. 실제 iPhone 하드웨어·실제 스크린리더 청취·실사용자 관찰은 확인 범위에 포함하지 않았다.

**측정으로 확인한 깊이**

12개 발화 예시의 자동 완료 화면에서 핵심 피드백 제목은 문서 y=1,513px, 연습 영역은 y=2,397px였다. 320px 너비에서는 각각 y=1,698px와 2,663px였다. 첫 화면에서 결과와 연습이 모두 보이지 않았다. 같은 회차를 기록에서 다시 열면 제목은 y=379px로 올라왔다. [전환 측정](primary/captures.json).

짧은 기록을 명시적으로 다시 연 경우에도 누적 목록이 앞에 있어 핵심 본문 시작은 약371px(390px 화면)/353px(320px 화면)였다. ‘표현 하나 연습’ **접힘의 제목**은 약1,103px/1,085px에 있었다. 닫혀 있는 안쪽 버튼을 첫 화면의 가시 행동으로 계산하지 않았다. [본문·연습 측정](secondary/metadata.json).

이는 예시 기록 길이에 따른 배치 측정이며 전체 사용자의 평균이나 실제 대기 시간은 아니다. 두 합성 기록의 시각이 같은 분인 것은 함께 생성했기 때문이므로, 실제 서비스에서 날짜가 항상 중복된다는 문제로 해석하지 않는다.

**상태·회복 경로에서 발견한 모순**

- [무발화](exceptions/no-user-speech.png): ‘피드백을 만들고 있어요’와 ‘확인된 사용자 발화가 없어 피드백을 만들지 않아요’가 동시에 남는다. 사용자는 기다릴 필요가 있는지 알기 어렵다.
- [분석 실패](exceptions/end-transcript-feedback-failed-viewport.png): 저장된 원문을 지키는 점은 좋지만, 준비 중 문구가 남고 실패 안내는 하단 알림에 겹친다. 상태 확인/재생성 행동도 아래로 밀린다.
- [일부 전사 누락](exceptions/end-transcript-partial-viewport.png), [기기 저장 실패](exceptions/end-transcript-device-failed-viewport.png): 원문·저장 상태를 거짓으로 완료 처리하지 않는 점은 유지해야 한다. 다만 여러 경고와 하단 알림이 겹쳐, 복구 행동과 보존된 내용을 구분하기 어렵다.

**권장하는 통화 이후 흐름**

통화 종료 확인 → 결과 준비 상태 → 이번 통화의 표현 하나 → 같은 뜻으로 한 번 말해보기 → 저장 확인·마무리

1. **통화 마무리 맥락을 유지한다.** 상대가 누구였고 통화가 끝났다는 사실을 짧게 이어 준다. 실제 단계에 맞춰 ‘마지막 말을 정리하고 있어요’ 또는 ‘대화 저장됨 · 표현 정리 중’ 한 줄을 표시한다. 읽을 원문은 사용자가 선택해서 열 수 있게 둔다. 불필요한 인위적 대기나 축하 애니메이션은 추가하지 않는다.
2. **회차 결과와 누적 보관함을 분리한다.** 통화 직후와 특정 기록 진입은 해당 회차 결과 모드다. 일반 복습 탭 진입은 남겨둔 일 하나를 이어가는 허브다. 탭을 늘릴 필요는 없지만, 회차 결과 위에 과거 목록이나 주간 분석이 먼저 오지 않아야 한다.
3. **첫 화면을 ‘하나의 결과·하나의 행동’으로 정한다.** 요약은 짧은 맥락으로, 근거 있는 잘한 점은 필요할 때 한 줄로 사용한다. 가장 도움이 되는 교정 또는 대안 하나를 원문/추천문/짧은 이유로 보여 준다. 모든 교정·추천 표현을 첫 화면에 나열하지 않는다. 교정할 근거가 없다면 빈 성과를 만들지 않는다.
4. **연습을 직접 시작한다.** 표현 아래의 ‘한 번 말해보기’ 같은 명확한 행동으로 진입한다. 같은 이름의 접힘과 버튼을 중첩하지 않는다. 기존의 원문 단서 → 답을 보지 않고 같은 뜻으로 말하기 → 필요하면 도움 보기 흐름은 유지한다. 실제 제공하지 않는 음성 녹음·자동 채점을 암시하지 않는다.
5. **저장이 확인되면 마무리 상태로 바꾼다.** 이전 연습 지시·미루기·중복된 홈 버튼을 그대로 두지 않는다. 직접 표시한 연습 기록이 저장됐다는 사실과 표현 하나를 보여 주고 기본 행동은 ‘마치기’로 정리한다. 다음 통화 목표나 회상 예약은 선택 행동으로 둔다. 숙달·실력 향상을 자동으로 선언하지 않는다.

첫 결과 화면의 정보 역할 예시이며 최종 시각 시안은 아니다:

>
> 내가 한 말: Yesterday I go to a cafe.
>
> 다음에 쓸 말: Yesterday I went to a cafe.
>
> 어제 있었던 일이므로 went로 말해요.
>

>

**상태별 표시 원칙**

| 실제 상태 | 전면 안내 | 주요 행동 |
| --- | --- | --- |
| 마지막 발화·저장 확인 중 | 통화 종료와 저장 확인 중임을 한 줄로 | 원문 확인. 안전한 이탈 가능 시점은 저장/전사 보존 조건과 함께 검증 |
| 대화 저장·분석 준비 중 | 대화 저장과 분석 준비를 구분한 짧은 상태 | 다른 화면 이동·이후 이어보기 |
| 결과 준비 완료 | 가져갈 표현과 이유 | 한 번 말해보기 / 오늘은 여기까지 |
| 저장 성공·분석 실패 | 대화는 저장됨, 분석은 준비되지 않음 | 같은 회차 다시 시도 |
| 무발화·근거 부족 | 표현을 정리할 근거가 없다는 단일 상태 | 마치기·다음 짧은 통화 |
| 일부 전사·저장 미확인 | 확인된 범위와 미완료 상태 | 원문 확인·재전송/수신분 마무리 |
| 연습 저장 실패 | 완료로 표시하지 않고 현재 표현 유지 | 같은 행동 저장 재시도 |
| 연습 저장 완료 | 자기 보고 연습의 저장 확인 | 마치기, 선택적으로 다음 통화 준비 |

피드백이 늦게 도착해도 다른 탭 사용자를 강제로 데려오지 않는다. 사용자가 원문을 열어 읽고 있다면 준비 완료 때문에 갑자기 원문을 접거나 스크롤을 옮기지 않는다. 결과 영역을 처음부터 안정된 자리에 두고 준비 여부를 알리며, 필요한 경우 사용자가 결과로 이동하게 한다.

**접근성과 시각 위계**

- 종료 전환 시 포커스가 긴 대화문 접힘에만 놓이지 않도록, 새 단계의 제목과 상태를 인지할 수 있는 읽기 순서를 설계한다. 실제 스크린리더 청취 검증은 별도로 수행한다.
- 저장·분석·연습 상태의 반복 알림을 줄이고, 상태 변경은 한 지점에서 명확히 알린다. 정상 안내와 복구 경고를 같은 회색 문단으로 연달아 나열하지 않는다.
- 320px에서도 첫 표현과 주 행동이 하단 도크에 가려지지 않아야 한다. 글자를 억지로 줄이거나 문장의 의미를 잘라내는 방식으로 해결하지 않는다.
- 색·굵기만으로 교정과 대안을 구분하지 않는다. 현재의 의미 구분·근거 접근은 유지한다.
- 기존 블루/네이비, 플랫 행동, 조작부의 글래스와 캐릭터를 유지한다. 읽는 영역의 장식·새로운 이모지·큰 캐릭터 애니메이션을 늘리는 방향은 권하지 않는다.

**실행 순서와 검증 기준**

1차: 정상/오류 상태 문구 일원화, 회차 결과와 복습 허브 분리, 결과가 원문 밑으로 밀리는 순서 수정. 2차: 첫 화면 표현·단일 행동과 연습 완료 상태 정리. 3차: 보관함·주간 분석·예약·표현 관리의 탐색 개선.

다음 시안은 실제 통화를 막 끝낸 사용자에게 5초 정도 보여 준 뒤 ‘통화가 끝났는가’, ‘기억할 표현이 무엇인가’, ‘어디를 누르면 되는가’를 설명하게 해 확인한다. 이는 앞으로 할 검증안이며 이번에 사용자 이해도나 학습 효과를 측정한 결과는 아니다. 모바일 390/320, 긴/짧은 통화, 느린 응답, 무발화, 실패·재시도, 늦은 완료, 연습 저장 성공/실패, 일반 재방문을 같은 기준으로 확인한다.

저장 확인 전 성공 금지, 상대/계정별 분리, 원문 근거, 교정과 대안 구분, 늦은 완료의 비강제 이동, 연습 중 답안 사본 숨김은 회귀 검사로 보존한다. UI 이해도는 이 기능 검사가 통과했다는 사실만으로 보장되지 않는다.
