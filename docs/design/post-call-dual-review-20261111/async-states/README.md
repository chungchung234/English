# 원문 열람과 피드백 준비 상태를 분리한 시안

2026-11-11 KST · 이미지 설계안

**선택 결과: 2안.** [구현·검증 기록](../implementation/README.md)에 실제 화면과 비동기 처리 기준을 기록했다. 아래 이미지는 선택 당시의 설계 참고 자료다.

세 시안은 동일한 예시 대화에서 `저장된 원문 열람과 피드백 준비 중 → 원문 위치를 유지한 준비 완료 → 사용자가 직접 연 피드백`을 비교한다. 피드백은 이유를 설명하고 질문으로 이어간 실제 발화의 관찰, 과거형 교정, 다시 쓸 표현을 함께 다룬다. 이 예시의 항목 구성을 모든 통화에 강제하지 않는다.

| 표시 순서 | 시안 | 차이와 검토할 점 |
| --- | --- | --- |
| 1 | [두 탭으로 분명하게](01-tabs.png) | 두 정보의 진입이 계속 보인다. 준비 상태가 탭에서 충분히 발견되는지 확인해야 한다. |
| 2 | [읽기는 그대로 피드백은 따로](02-separate-feedback.png) | 처음부터 확보한 하단 공간의 준비 상태가 피드백 진입 버튼으로 바뀐다. 읽기 위치는 유지되지만 하단 공간을 계속 차지한다. |
| 3 | [대화 맥락에서 발견](03-context-panel.png) | 대화 위에 패널을 열어 근거와 피드백을 가까이 둔다. 긴 피드백과 큰 글자에서는 패널이 좁아질 수 있고 전체 보기까지 한 단계가 더 필요하다. |

첫 두 프레임은 원문과 읽는 위치를 같게 유지하고, 피드백 진입 영역만 바꾸는 설계 의도를 보여준다. 생성 이미지이므로 실제 위치 보존·반응형·접근성 동작을 검증한 증거는 아니다.

## 준비 상태를 해석하는 기준

- 첫 프레임은 기록 저장이 확인된 뒤 피드백을 생성하는 상태다. 통화를 끊자마자 모든 전사와 저장이 완료된다는 뜻이 아니다.
- 마지막 발화·저장 확인 전에도 받은 원문은 열람하게 하며, ‘마지막 대화 확인 중’과 ‘피드백은 대화 정리 후 준비돼요’를 구분한다. 이 초기 상태는 시안 하단의 예외 주석으로 명시했다.
- 피드백이 실패해도 원문은 유지한다. 해당 영역에 실패와 재시도를 제공한다. 실패 화면 전체를 이번 이미지에 별도로 그리지는 않았다.
- 생성 예상 시간·진행률·점수는 제시하지 않는다. 준비 완료가 자동 화면 전환이나 스크롤 이동을 일으키지 않는다.
- ‘마치기’는 종료만 한다. 연습·복습 미루기를 기록하지 않는다. 생각 시간 버튼, 혼자 말하기, 자기보고 수행 버튼, 표현 1개 제한은 없다.

시안 선택 뒤에는 마지막 전사 지연·저장 실패·피드백 실패·긴 원문·긴 피드백·큰 글자·재방문 상태까지 이어서 구체화해야 한다. 캐릭터의 선제적 종료는 계속 [검토 문서](../../character-initiated-hangup-review-20261111.md)의 후보로만 남기며 이 시안에 추가하지 않는다.
