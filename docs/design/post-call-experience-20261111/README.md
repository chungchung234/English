# 통화 이후 경험 개선

2026-11-11 · 구현 및 배포 검증

통화를 마친 사용자가 결과를 찾기 위해 긴 대화문을 지나야 했고, 연습을 저장해도 이전 과제와 중복 이동 버튼이 남았다. 이번 변경은 **통화 종료 → 표현 하나 → 직접 말해보기 → 저장 확인·마치기**로 읽는 순서를 정리한다.

## 근거와 비판적 재검토

[변경 전 감사](../post-call-audit-20261111/README.md)에서 12개 발화의 자동 완료 결과 제목은 y=1,513px에 있었다. [연구 문서](../../research/post-call-experience-20261111.md)는 NN/g 점진 공개, W3C 상태 안내·포커스·리플로우, 회상 연구 원문을 확인하고 적용 범위를 구분한다.

‘표현 하나’는 최적 학습량이 증명됐다는 뜻이 아니다. 종료 직후 읽기와 시작 부담을 줄이는 제품 가설이다. WCAG의 320px 기준도 모든 내용을 한 화면에 넣으라는 요구가 아니다. 긴 문장과 큰 글자는 세로 스크롤로 읽을 수 있게 유지한다. 사용자 이해도나 학습 향상은 자동화 검사에서 측정하지 않았다.

## 구현한 흐름

| 단계 | 변경 |
| --- | --- |
| 통화 종료 | 상대와 종료 맥락을 이어 주고 실제 마지막 전사·저장 확인을 표시한다. 대화문은 같은 화면의 접힌 영역에서 즉시 열 수 있다. |
| 결과 준비 | 저장·준비·무발화·실패·미완료를 구분한다. 준비 안내와 실패·무발화 안내가 동시에 남지 않는다. |
| 결과 | 유효한 원본 회차의 표현 하나, 원문, 추천문, 이유, 직접 연습 행동을 앞에 둔다. 전체 피드백·근거·관리는 펼쳐 볼 수 있다. |
| 짧은 연습 | 단서만 보고 같은 뜻으로 말하고 필요하면 표현을 다시 본다. 원문·다른 화면의 답안 사본은 숨긴다. 녹음·자동 채점으로 오해하지 않게 표시한다. |
| 저장·회복 | 확인 전에는 완료로 표시하지 않는다. 실패하면 현재 연습 안에서 같은 요청을 다시 전송한다. 충돌은 최신 상태를 확인한 뒤 해결한다. |
| 마무리 | 서버 확인 후 이전 과제·미루기·중복 홈을 제거한다. 표현과 저장 확인, ‘마치기’, 선택적인 다음 통화 준비만 남긴다. |
| 다음 방문 | 일반 복습 탭은 남겨둔 표현 하나와 보관함을 중심으로 연다. 특정 회차와 주간 분석은 각각의 문맥을 유지한다. |

기존 캐릭터·색상 체계와 조작부의 글래스는 유지하고 읽는 영역과 주 행동은 평평하게 정리했다. 병행 작업으로 배포된 연결음·600ms 종료 전환도 통합해, 마이크는 즉시 멈추고 짧은 종료 표시 뒤 이번 결과 화면으로 이어진다.

## 독립 검토에서 보완한 동작

- 연습 화면에서 나간 뒤 이전 연습이 새 통화 결과를 숨기지 않도록 시각 상태를 정리한다. 미확인 저장 요청은 기기 대기열에 유지한다.
- 늦은 분석·저장·회차 조회 응답이 사용자가 선택한 탭을 되돌리지 않는다.
- 늦은 기록 갱신이 주간 분석 화면을 다른 회차로 덮지 않는다.
- 연습 실패 안내를 해당 화면 안에 두고, 같은 요청으로 재시도하며, 성공 뒤 실패 토스트가 남지 않게 한다.
- 연습할 표현이 없는 정상 피드백도 읽음 처리한다. 미완료·오류 상태를 읽은 성과로 처리하지 않는다.
- 연습 시작·완료는 제목에 포커스를 두고, 자동으로 준비된 결과는 상태로 알린다. 사용자가 읽는 대화문을 자동으로 접지 않는다.

## 검증

실제 앱을 Chromium에서 실행하고 인증·음성·AI 응답은 합성 fixture로 대체했다. 새 경험 검사는 PGlite의 실제 SQL/RLS/RPC와 IndexedDB를 사용한다. 390×844와 320×568, 긴 대화, 느린 저장·분석, 무발화, 서비스 실패, 오프라인 저장, 명시적 재전송, 재접속, 탭 이동, 주간 분석의 늦은 응답을 검사한다. 실제 사용자 계정·대화문에 접근하지 않는다.

[화면별 비교](evidence.html) · [원시 측정](metrics.json). 짧은 예시의 연습 버튼은 두 화면 크기에서 하단 메뉴 위에 보이고 가로 넘침이 없다. 실제 iPhone·스크린리더 청취·사용자 이해도·학습 효과는 검증 범위에 포함하지 않았다.

기존 회귀 검사는 계정·상대·원본 회차 분리, 저장 전 성공 금지, 중복 방지, 발화 보존, 근거·제외·복원, 예약 회상, 주간 목표, 음성 제어, 캐릭터 alpha 렌더링을 유지한다. 기본 테스트 222개와 타입 검사를 통과했고, 세부 브라우저 결과와 공개 배포는 [배포 확인](deployed-verification.json)에 기록한다.
