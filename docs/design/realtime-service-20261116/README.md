# 실시간 통화 복구와 서비스 안정화

사용자가 말을 마친 뒤 전체 답변 작성·별도 전체 음성 합성을 기다리던 경로는
실시간 통화의 첫 소리를 늦췄다. 새 통화의 기본 경로를 직접 WebRTC 음성으로
되돌린다. 모델이 생성한 음성을 도착하는 대로 재생하고, 원문 저장·기억 영수증·
통화 후 학습은 별도로 진행한다. 모델·캐릭터 voice·발화 종료 판단의 low 설정과
원문 ACK·계정/캐릭터 격리·잊기 경계는 보존한다. 답변·질문·인사 길이 제한을
더해 속도나 친근함을 개선한 것으로 취급하지 않는다.

## 구현한 변경

- 운영 config는 `realtime_webrtc_v1`을 명시하고 오래된 작성 대화 플래그와 무관하게
  실시간 음성을 선택한다. 이전 클라이언트의 정리·호환용 endpoint는 남아 있다.
- 이전 통화의 업로드는 새 통화 연결을 막지 않는다. 현재 원문과 저장 확인 조건은
  그대로다. 학습 상태 조회부터 연결 제한시간·취소를 적용하고, 취소 후 늦게 허용된
  마이크는 즉시 정리한다. 503은 개인 네트워크 확인 대신 서비스 재시도로 안내한다.
- 직접 RTC는 잡음 후보 하나만으로 음소거·취소하지 않는다. 같은 후보의 지속된
  로컬 음성 또는 로컬 확인을 통과한 최종 발화를 근거로 해당 응답을 취소하며
  명시적 중지는 즉시 동작한다. 늦은 이전 전사는 새 응답을 취소하지 않는다.
  RTC를 임시 음소거하면 건너뛴 프레임을 복원할 수 없으므로 같은 커서 재개로
  표현하지 않는다. 버퍼 재생 방식의 재개와 직접 RTC의 지속 재생을 구분한다.
- 지연 관측은 같은 브라우저 시계에서 수신한 발화 종료·전사·저장 ACK·요청·출력
  시작을 연결한다. native reference에서 관측한 decoded stream 샘플과 provider의
  출력 시작을 구분한다. 실제 스피커 청취나 물리적 발화 종료의 측정으로 부르지 않는다.
  숫자·열거형·앱 UUID만 보관하고 provider ID·음성·전사 원문을 진단에 넣지 않는다.
- 진단과 기억/재생 영수증은 실패 대기와 항목별 진행을 적용한다. 앞의 무효 항목이
  뒤의 정상 항목을 막지 않으며 원문·불변 영수증·ACK를 임의 삭제하지 않는다.
- 대화 정책은 실제 디테일과 캐릭터 관점에 반응하고 표현 도움 뒤 원래 이야기로
  돌아오도록 보강했다. 서로 다른 통화의 동일 시작 문구도 최근 스타일 이력에
  남겨 반복 증거를 감추지 않는다. 새 모델 단계나 강제 대화 틀을 추가하지 않는다.

## 503·CPU/I/O 장애 조사 및 긴급 DB 수정

운영 REST 요청에서 `503/PGRST002`와 스키마 캐시 조회 실패를 확인했다.
당시 관리 health는 DB·Auth 정상, REST 비정상이었다. 캐시 재로딩 뒤에도 같은
오류가 이어져 프로젝트 재시작을 요청했다. 이후 패치·서버 배포와 두 번째 재시작을
진행했지만 DB·REST·Auth는 아직 비정상이다. 관리 API의 간단한 읽기도 PostgreSQL
연결 거부로 실패한다. 재시작 접수를 서비스 복구 완료로 보지 않는다.

후속 CPU·디스크 I/O 경고와 반복 DB 오류를 조사해 앱이 업무 상태 충돌에
SQLSTATE `40001`을 쓰고 있음을 확인했다. 확인한 PostgREST v14.18은 Hasql의
transaction runner를 사용하며, 허용 의존성의 공개 태그 소스는 이 SQLSTATE를
횟수 제한·대기 없이 재시도한다. 종료된 통화·이미 바뀐 권한·폐기된 이력처럼
같은 입력으로 해결되지 않는 실패가 DB 연결과 CPU·로그를 소비할 수 있다.
실제 Supabase 바이너리의 의존성을 추출한 것은 아니며, 공개 소스와 운영 관측을
함께 근거로 삼는다. 이 문제를 단순히 컴퓨트가 작아서 생긴 것으로만 판단하지 않는다.

`202611160003`은 명시된 앱 함수 29개의 업무 예외 60곳만 `PT409`로 바꾼다.
같은 조건·메시지를 HTTP 409 충돌로 종료하고 실제 엔진의 직렬화·deadlock 처리는
바꾸지 않는다. 기존·변경 본문 fingerprint와 개수를 검사하고 알 수 없는 본문은
거부한다. 독립 검토에서 140개 앱 함수의 나머지 본문과 OID·소유자·ACL·보안 속성·
search_path를 대조했다. 운영 적용 전 29개 기존 본문을 확인했고 적용 뒤 모두 새
fingerprint와 일치했다. 앱 데이터·계정 권한은 이 긴급 수정에서 바꾸지 않았다.

[공식 소스와 해시](operations/postgrest-retry-source-evidence.json),
[독립 검토](operations/conflict-independent-review.json),
[운영 적용·대조](operations/conflict-hotfix-applied.json)를 보존한다.

운영의 작성 대화 플래그도 비활성화했다. 일회성 함수에서 실제 런타임의 false 값을 확인했고 모델·DB 요청은 없었다. 확인 함수는 삭제 뒤 별도 목록에서 부재를 확인했다. [실제 런타임 확인](operations/runtime-transport-flag-verification.json)을 보존한다.

## Database 권고 정리와 운영 설정

`202611160001`은 소유권·승인 조건을 유지한 채 RLS 인증 재평가 6건, 실제 접근
경로의 인덱스 8개, 자동 RLS event trigger의 불필요한 클라이언트 실행 권한을
정리한다. 서버 전용 12개 테이블의 기본 차단과 정상 RPC 권한은 유지한다.
인덱스는 일반 CREATE INDEX이며 비차단 생성으로 설명하지 않는다. 운영 테이블
크기를 확인했고 긴 잠금 취득 대기는 거부한다. 모든 FK 권고를 지우기 위한 역순
중복 인덱스나 사용 통계만 보고 삭제하는 인덱스는 추가하지 않는다.

사용하지 않는 익명 로그인 비활성화는 개별 PATCH 뒤 독립 GET으로 확인했다.
유출 비밀번호 보호 활성화 요청은 HTTP 402로 거부됐고 비활성 상태를 다시 확인했다.
요금제나 컴퓨트를 자동 업그레이드하지 않았다. 다른 SMTP·소셜 로그인·계정·세션
설정은 이 작업의 변경 대상이 아니다. [실제 설정 결과](operations/auth-applied.json)를
기준으로 적용 범위를 구분한다.

## 검증과 한계

[로컬 검사](local-checks.json), [브라우저 범위](local-browser/verification-scope.json)를
보존한다. 연결 18개와 실시간 흐름 8개, 기존 음성 안정성 검사가 통과했다.
새 학습 조회 timeout/취소 실패를 먼저 재현했고 수정 뒤 늦은 완료·마이크 정리·
재시도를 확인했다. 320/390px·글자 125%에서 말하기·듣기·503 안내 6장을 직접 열었다.

모의 인증·DB·RTC·모델과 native WebAudio/VAD 동작을 사용한 앱 검사다. 실제
승인 계정의 PC Chrome·Edge 통화, 물리적 소음 억제, 발화 종료부터 첫 스피커
출력까지의 지연, 반복 통화에서 친구 같은 느낌을 입증한 결과로 표현하지 않는다.
서버 준비 시간이나 캐시 적중만으로 체감 개선을 주장하지 않는다. 느려진 문장별
합성 실험 PR #29는 병합·활성화하지 않는다.

앱 릴리스 `ec7626246f3e8ee25edd4565fa3f517fc4297f27`의
[CI](https://github.com/chungchung234/English/actions/runs/43892362098)는 타입·단위·
학습 평가·브라우저 검사를 통과했지만, DB 연결 거부로 서버 배포 단계에서 실패했다.
별도 HTTPS 서버 배포는 완료했고 [실제 서버 소스](operations/production-source-only.json)의
109개 검사·모듈 16개·WS 파일 19개가 해당 코드와 일치했다. 최종 DB 메타데이터
69개 검사는 서비스 장애로 실행하지 못했다.

새 Pages 게시는 진행되지 않았다. 2026-11-16 15:29 UTC의 공개 웹 빌드는
`e3d34994ddde31b6a9a05545c1f20a9c31f2df1b`로 이전 버전이다. 실제 승인 계정의
정상 통화와 전체 배포 완료를 주장하지 않는다.

동일 프로젝트를 데이터·설정을 유지하며 중지·재개하려던 요청은 중지 단계에서
HTTP 500 `Failed to verify backup status before pausing`로 실패했다. 중지 상태는
관찰하지 못했고 재개나 과거 백업 복원은 요청하지 않았다. 디스크 설정은 2GB지만
사용량 조회가 실패해 디스크 가득 참은 미확정이다. 앱 DB 크기만으로 WAL·로그의
공간 사용을 배제할 수 없다. 요금제·컴퓨트는 변경하지 않았다.

공개 파일 대조·승인 계정 통화 검증이 남아 있다.
