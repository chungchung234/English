# 이메일 로그인 발송 오류와 복구

2026-11-10 KST에 신고된 로그인 실패를 실제 제공자 설정, 계정 상태, 제한적인 발송 요청과 로그로 점검했다. 비밀번호·코드·세션·SMTP 사용자명은 이 문서나 로그에 기록하지 않는다.

## 확인한 원인과 상태

- 신고 계정은 존재하며 이메일 인증과 서비스 승인 상태가 정상이다. 계정·승인 목록 변경으로 우회하지 않았다.
- SMTP가 미설정된 상태는 아니다. 발송 서버가 `google.com:465`여서 Gmail의 SMTP 주소인 `smtp.gmail.com`으로 서버 주소만 수정했다. 발송 계정·비밀번호·기타 SMTP 설정은 그대로 유지했음을 읽어서 비교했다.
- 주소 수정 후 실제 OTP 요청은 HTTP 500 `Error sending magic link email`로 실패했다. 제공자 로그에서 Google SMTP의 `535: Username and Password not accepted`를 확인했다. 주소 수정만으로 복구됐다고 보고하지 않는다.
- 인증메일 한도는 프로젝트 시간당 30건, 동일 수신자 재발송 간격은 60초다. 실제 `/otp` 로그에서 `over_email_send_rate_limit`과 `over_request_rate_limit` HTTP 429를 모두 확인했다. 한도 증가나 이메일 인증 해제로 해결하지 않았다.
- 기존 UI는 발송·검증 요청 중 중복 제출을 막지 않았으며, 재발송 대기 안내와 기존 코드 진입 경로가 부족했다. 반복 요청이 한도 소진을 악화할 수 있으나 과거 요청 전체가 중복 클릭 때문이라고 단정하지 않는다.

## 운영자가 완료할 작업

1. 발송에 사용하는 Google 계정에서 2단계 인증과 [앱 비밀번호](https://support.google.com/accounts/answer/185833?hl=ko) 사용 가능 여부를 확인한다. 조직 계정 정책이 앱 비밀번호를 막으면 관리자가 허용한 SMTP 발송 수단이 필요하다.
2. [Supabase Authentication → SMTP](https://supabase.com/dashboard/project/domkmxmwmihcfadophfg/auth/smtp)에서 Host `smtp.gmail.com`, Port `465`, 발송 계정 Username과 Sender email을 확인하고 Password에 해당 계정의 앱 비밀번호를 설정한다. 일반 Google 로그인 비밀번호를 그대로 사용하지 않는다. 비밀번호를 채팅·이슈·저장소로 전달하지 않는다.
3. SMTP 설정을 저장한 뒤 기존 제한이 해제된 상태에서 인증메일을 한 번 요청한다. 메일함·스팸함을 확인하고 앱에서 최신 코드를 입력한다. 코드도 채팅에 전달하지 않는다.
4. 발송 API 성공과 수신함 도착, 실제 코드 검증, 승인 계정의 앱 진입을 각각 확인한다. 실패하면 재발송을 반복하지 않고 제공자 로그에서 SMTP 거부를 확인한다.

## 앱의 재발 방지

- 발송·검증 중 즉시 잠금으로 중복 제출과 이메일 변경을 막는다.
- 발송 성공 후 60초 재발송 대기, HTTP 429의 `Retry-After` 및 알려진 초 단위 제한 메시지를 반영한다. 서버가 재시도 시간을 주지 않은 시간당 메일 한도는 보수적으로 1시간 대기를 표시한다. 정확한 서버 한도 해제 시각을 안다고 주장하지 않는다.
- 대기 상태는 새로고침과 다른 탭에 공유한다. 프로젝트·요청 제한은 같은 브라우저에서 이메일을 바꿔도 유지한다. 이 로컬 장치는 서버 제한을 대체하지 않는다.
- 발송 결과가 불확실하면 메일함 확인 안내와 60초 대기를 적용한다. 자동 재발송·자동 코드 검증은 하지 않는다.
- 이미 받은 코드로 바로 진입할 수 있으며, 발송 제한 중에도 검증 요청 자체가 제한되지 않았다면 코드를 입력할 수 있다. 이메일을 바꾸면 기존 코드 입력을 비우고 수신자를 다시 확인한다.
- 코드·비밀번호는 대기 상태에 저장하지 않는다. 인증 성공 후 기존 서버 승인 검사를 그대로 통과해야 앱에 진입한다.
- 로그인 화면의 오류 안내는 문서 흐름 안에 배치해 모바일에서 코드 입력·로그인 버튼을 덮지 않는다.

## 검증 범위

`test/email-login-browser.mjs`는 합성 API 응답으로 중복 발송·검증, 60초 대기 복원, `Retry-After`, 시간당 한도 fallback, 초 단위 제한 메시지, 네트워크 실패, 기존 코드 경로, 이메일 변경, 코드 미보관, 승인 거부를 검증한다. 실제 메일을 발송하지 않는다. 기존 앱 전체 브라우저 검사와 빌드 CSP 검사에도 포함된다.

실제 수신함 도착과 승인 계정의 로그인은 SMTP 자격 증명 갱신 후 별도로 확인해야 한다.
