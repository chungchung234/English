# 통화 후 고도화 — 실제 사용자·품질 평가 절차

작성일: 2026-11-10 KST. 대상은 [E01~E05](post-call-plan.md#13-실제-통화-검증-이후-고도화-우선순위)다. 기능·자동 인수와 실제 사람의 판단·학습효과를 구분한다.

**현재 실제 참여자·검토 자료는 없다.** 사용자가 이번 작업에서 이를 확인했다. 합성 테스트를 참여자 관찰이나 실제 활용 탐지 정확도로 보고하지 않는다. 활용 표시는 관찰과 사용자 확인 수준으로 유지하며, 평가 결과가 있어도 도구가 자동으로 성공·숙달 표시를 활성화하지 않는다.

## 모집과 데이터

기존 계획의 성인 영어 학습자 6~8명을 대상으로 첫 이용·반복 이용·건너뛰기 선호·장기 복귀 상황을 포함한다. 동일 참여자의 반복 방문을 새 참여자로 세지 않는다. 참여자 모집·연락은 별도로 승인된 진행자가 수행한다. 이번 구현 작업에서 다른 사람에게 연락하지 않았다.

참여자가 실제 통화·전사와 교정 처리, 추가 의도 설명의 사용 범위를 이해하고 동의한 뒤 진행한다. 언제든 건너뛰거나 중단할 수 있다. 원본 음성 파일을 연구 목적으로 새로 녹음하지 않는다. 이름·이메일 대신 참여자 코드를 사용하고 연락처 대응표는 별도 보호된 장소에 둔다. 공유 보고서에는 집계값만 내보내며 대화 원문·인증 정보·실제 회차 ID를 저장소에 올리지 않는다.

검토용 발화가 필요하면 참여자의 동의 범위 안에서 접근을 제한한다. 사용자 계정의 보류·제외·잊기 정책을 연구용 추천이나 다음 통화 문맥에서 해제하지 않는다. 오프라인 라벨은 해당 원문 버전과 연결하고, 버전이 달라지면 재검토한다.

## 관찰 과제

| 시점 | 참여자 과제 | 기록할 것 |
| --- | --- | --- |
| 첫 통화 직후 | 설명 없이 피드백 확인, 한 표현 선택 또는 건너뛰기 | 추천 이유 이해, 행동 발견, 도움 요청, 부담 |
| 교정 이의 사례 | 실제 의도 보충, 재검토 결과 확인, 수락 또는 유지·닫기 | 원래 발화와 추가 설명 구분, 이의 해결 여부, 부적절한 재추천 |
| 즉시 연습 | 표현을 보고 말하거나 가린 뒤 자기보고 선택 | 수행 시도·서버 저장, 도움이 있었는지. 지연 회상과 분리 |
| 선택한 1·3·7일 후 | 먼저 표현을 가리고 회상, 필요하면 힌트, 어려움·도움·독립 수행 선택 | 실제 예정일·발생일·서버 수신일, 회상 도움, 미루기·중단 |
| 다음 통화 | 선택한 목표 표현을 쓸 기회가 있는지 관찰하고 자유롭게 대화 | 기회와 근거 발화, 따라 말하기·힌트·새 상황의 구분 가능 여부, 대화 부담 |
| 주간 요청 | 실제 168시간 분석 확인 후 계속/새 목표 하나 선택 | 범위 이해, 목표 선택 이유, 다음 통화·지연 회상 연결 |

사용자에게 다음 버튼의 위치나 정답 표현을 미리 알려주지 않는다. 저장되지 않았는데 저장됐다고 이해하거나 다른 계정·상대 기록으로 혼동한 사례를 별도로 기록한다. 진행자가 알려준 도움과 제품의 힌트는 구분한다.

## 사람의 품질 라벨

E02 교정 검토는 원문의 실제 사용자 발화, 별도 표시된 추가 설명, 제안된 표현·이유를 함께 본다. 인용의 존재와 교정 내용의 적절성은 다른 판단이다. 발화자의 의도 확인과 언어 검토자의 문법·의미 평가는 각각 기록한다. 불일치는 보류하고 가능한 경우 추가 검토자에게 판정을 요청한다. 모델의 자기평가를 사람의 평가로 입력하지 않는다.

E04는 다음을 독립적으로 라벨링한다.

- `kind`: 실제 사용자 발화에 대상 표현이 관찰됨 / 판단 불가 / 불확실. 문자열 관찰은 자발적 활용이나 숙달을 뜻하지 않는다.
- `opportunity`: 사용할 기회 있음 / 없음 / 불명. 어시스턴트가 한 질문 등 근거를 확인한다. 준비된 목표가 있었다는 사실만으로 기회 있음을 확정하지 않는다.
- `mode`: 예문 반복 / 힌트 후 사용 / 새 상황 활용 / 구분 불가. 구분할 근거가 없으면 판단 불가를 유지한다.
- `appropriate_use`: 상황에 적절함 / 부적절함 / 불확실. 기회가 확인되고 이 판단도 가능한 사례만 적절한 활용률의 분모로 사용한다.

원문 버전이 맞지 않거나 다른 회차·상대의 근거, 사용자 아닌 발화, 검토하지 않은 사례는 성공 분자에 넣지 않는다. 사람의 검토 상태 `confirmed` 역시 학습 숙달을 뜻하지 않는다.

## 실행 도구

합성 문장·부재·어절 경계·다른 시제·예문 반복·유니코드 등 고정 사례를 검사한다.

```sh
npm run eval:learning
```

실제 검토 자료가 준비되면 보호된 로컬 파일로 입력한다. 결과에는 원문이나 사례 ID가 출력되지 않는다.

```sh
node --experimental-transform-types scripts/evaluate-learning-enhancements.mjs \
  --predictions /private/predictions.json --labels /private/labels.json \
  --output /private/evaluation-summary.json
```

입력 형식은 `schema_version: 1`, `cases` 배열이다. 예측의 각 사례는 `id`, `source_version`, `observation: {kind,mode}`를 포함한다. 라벨은 같은 `id`·`source_version`과 `kind`, `mode`, `opportunity`, `appropriate_use`를 포함한다. 중복·모르는 사례·이전 버전의 라벨은 거절한다.

실제 대화의 독립적인 사람 검토에만 예측 `origin: real_conversation`, 라벨 `origin: human_review`, `independent_review_attested: true`, 익명 `reviewer_code`를 사용한다. 합성 자료에는 `synthetic_fixture`를 사용한다. 자료가 없으면 사람의 품질·참여자 수·학습효과를 측정했다고 표시하지 않는다. 도구는 실시간 서버의 출처 유효성을 다시 조회하지 않으므로, 실제 적용 판단 전에 서버 정책도 확인한다.

## 관찰 기간과 판단

기준 회차를 14일간 수집하고, 지표별 관찰창이 끝난 대상과 미성숙 대상을 구분한다. 전체 회차 전환은 최대16일 관찰 +72시간 전송 유예, 다음 통화는 7일 관찰 +72시간 유예를 적용한다. 미성숙·미수신은 실패로 간주하지 않는다. `observationWindows()`는 동일 기준으로 대상 수를 분리한다.

저장 손실·계정 혼동·저장 오인 1건이라도 있으면 공개 확대를 보류한다. 같은 핵심 행동에서 독립된 2명 이상이 막히면 수정 후 재관찰한다. 추천 적합성, 지연 회상, 실제 활용, 재방문과 함께 부담·저장 실패·통화 연결을 확인한다. 목표 수치는 기준값과 표본을 확보한 뒤 정하며, 6~8명의 탐색 결과로 통계적 학습효과나 인과관계를 주장하지 않는다.

## 아직 필요한 실제 증거

참여자 모집·동의, 실제 과제 관찰, 교정·활용의 사람 라벨, 1·3·7일 지연 회상과 성숙한 재방문 집단이 필요하다. 구현·합성 평가·자동 인수가 통과해도 이 항목은 실제 자료가 준비될 때까지 미완료로 유지한다.
