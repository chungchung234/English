## 별도 계측 점검

해당 회차의 **`call_connected` 이벤트는 최종 조회 시 0건**이었다. `feedback_ready`와 유효한 `feedback_exposed`는 각각 1건이다. 따라서 실제 대화·저장 성공과 별개로, RTC 연결 계측의 서버 수신까지 통과했다고 보고하지 않는다.

현재 코드는 실제 PC의 `connected` 상태에서 연결 사건을 기기 대기열에 넣고 바로 전송을 시도한다. RPC 실패 시 기기에 남아 재시도하며, 기기 저장 자체가 실패하면 사건이 남지 않을 수 있다. 이전 프런트엔드에는 이 계측이 없었다. 이번에 처음 열린 클라이언트 버전과 기기 대기열은 직접 확인하지 못했으므로, 누락 원인을 확정하거나 과거 사건을 사후 생성하지 않았다. 최신 페이지에서 시작한 통화의 연결 계측을 별도로 확인할 항목으로 남긴다.

음성 작업의 SDP 교환 성공 자체를 WebRTC 연결의 독립 증거로 취급하지 않는다. 이번 실제 대화 확인은 사용자의 실제 통화 수행과 양쪽 전사·실제 서버 작업을 함께 근거로 한다.

## 확인 범위

- 정상 Google 승인 계정·Alex 1회와 페이지 새로고침 후 저장 이력 복원에 대한 결과다. 이번 검사에서 새 Google 동의나 이메일 OTP 로그인을 다시 수행한 것은 아니다.
- 새로고침 후 복원은 통화 중 네트워크 단절·OS 종료 후 RTC 복구와 구분한다. Mia·Juno, 다른 기기·브라우저의 실제 음성 품질까지 일반화하지 않는다.
- 앱 브라우저 제어 도구가 연결되지 않았고 공유 Desktop도 사용자 UI에 제공되지 않아, 통화·마이크·새로고침 조작은 사용자가 맡았다. Codex는 읽기 전용 운영 DB 검증과 결과 기록을 수행했다.
- 이메일·비밀번호·토큰·회차 ID·대화 원문은 이 문서에 포함하지 않았다. 검증을 위해 승인 목록이나 인증 설정을 바꾸지 않았으며 실제 통화 기록도 삭제하지 않았다.

SMTP 코드 전달, 관리형 자동 백업·재해 복구, 실제 사용자 연구는 [운영 보고서](production-readiness-20261110.md)의 별도 과제로 유지한다.
