# 시시콜콜 기억 고도화 실행 계획

작성: 2026-11-10 (한국 시간). 사용자 요청: 서비스 실행 모델과 작업 에이전트를 모두 티어링하고 계획을 실제 구현으로 진행한다.

## 이번 배포 범위

1. **혼합 검색:** 의미 벡터와 키워드 검색을 결합하고 최신 기록을 보완한다. 원문 근거, 사용자·상대 경계, 최대 12건/16KB의 주입 상한을 유지한다.
2. **기억 관리:** 상대별 사실 6개 항목을 확인·수정·잊기, 회차별 기억 제외·복원을 제공한다. 원문 삭제와 기억에서 제외하는 동작을 구분하고 백업에도 기억 정책을 보존한다.
3. **평가:** 실제 SQL 엔진에서 검색 순위·수정·잊기·상대 분리·복원·캐시 무효화를 검증한다. 브라우저에서 편집과 실패·통화 중 제한을 확인한다.

이번 범위의 완료 기준은 계획서, 코드, 재현 가능한 평가, 테스트, DB·함수·웹 배포 및 공개 결과 확인이다.

## 작업 에이전트 티어

| 역할 | 모델 | 배정 이유 |
| --- | --- | --- |
| 설계·격리·잊기 정책 검토 | `gpt-6-astra`, high | 검색·요약·캐시·복원을 가로지르는 경계 검토 |
| SQL 및 서버 구현 | `gpt-6.1-sol`, high, 분야별 두 작업 | 상태 전이, 경쟁 조건, 인용 검증과 외부 API 연결 |
| 화면·브라우저 구현 | `gpt-6-luna`, high | 합의된 API를 사용하는 제한된 UI 범위 |
| 통합·평가·배포 | 현재 주 에이전트 | 충돌 해결, 실제 결과 확인 및 최종 판단 |

담당 파일을 분리하고 공유 API를 먼저 합의한다. 각 작업은 독립 커밋·배포하지 않으며 통합 후 하나의 검증 결과로 배포한다. 에이전트 모델 티어링의 비용 절감률은 측정하지 않았으므로 수치로 주장하지 않는다.

## 서비스 실행 모델 티어

| 기능 | 기본 모델/처리 | 비용 제어 |
| --- | --- | --- |
| 사실 편집·잊기·제외, 접근 검사, 순위 결합 | SQL/코드 | 생성 모델 호출 없음 |
| 의미 검색 | `text-embedding-3-small`, 512차원 | 빈 검색에는 호출 없음, 입력/모델/기억 버전별 재사용 |
| 실시간 음성 | `gpt-realtime-mini` | 응답 512토큰, 기존 컨텍스트 정리 |
| 음성 전사 | `gpt-4o-mini-transcribe` | 기존 발화 전사 |
| 통화 중 요약 | `gpt-4.1-mini` (`CHECKPOINT_MODEL`) | 변경된 발화만 처리, 기억 버전이 다른 캐시 제외 |
| 통화 교정·사실 추출 | `gpt-4.1-mini` (`COACH_MODEL`) | 원문 근거 검증, 분석 캐시 |
| 7일 분석 | `gpt-4.1` (`ANALYSIS_MODEL`) | 사용자 요청 시 실행, 부분 결과 재사용 |

UTC 일일 요청 예산은 음성 연결 30, 회차 교정 20, 주간 분석 3, 통화 요약 60, 분할 분석 80, 임베딩 200으로 분리한다. 임베딩 색인 한 번에는 최대 4개 문서를 처리하므로 요청 수 제한은 금액 상한과 다르다.

승인되지 않은 요청은 어떤 AI 호출보다 먼저 차단한다. 상위 모델로의 무조건적인 자동 재시도는 도입하지 않는다. API 실패나 임베딩 예산 소진 시 검색은 키워드 방식으로 동작하며, 사용 가능한 근거 범위를 표시한다.

## 저장과 검색 설계

- 사용자·상대별 기억 버전을 관리한다. 사실 변경·잊기·회차 제외/복원은 버전을 원자적으로 증가시킨다.
- 이전 버전의 체크포인트를 새로운 대화 지침에 섞지 않는다. 생성 중 기억 정책이 바뀌면 결과를 적용하지 않고 재시도한다.
- 사실을 수정하거나 잊으면 이전 자유 형식 요약에서 정보가 다시 나타나지 않도록 그 시점 이전 회차의 검색 문맥을 보수적으로 제외한다. 다른 구조화된 사실은 유지하고, 음성 모델에 근거 원문을 무조건 전달하지 않는다.
- 회차 제외는 요약·사실 추출·임베딩 후보·검색에 공통으로 적용한다. 재분석·재색인·오래된 백업 복원으로 기존 제외 정책을 해제하지 않는다.
- 임베딩은 현재 회차의 최신 분석, 모델 식별자, 512차원, 문서 해시와 연결한다. 저장 직전에 최신 분석·기억 버전을 다시 확인한다.
- 첫 버전은 PostgreSQL 배열의 정확한 코사인 유사도와 순위 결합을 사용한다. 조회 후보 상한과 제한 여부를 표시하며, 대규모 사용자 이력에는 pgvector/HNSW 전환을 검토한다. 벡터 확장 없이 같은 SQL을 로컬 PostgreSQL 테스트에서 검증할 수 있다.
- 이력 색인은 사용자가 실행하는 작은 배치로 진행한다. 통화 연결 경로에서 전체 과거 이력을 임베딩하지 않는다.

## 평가와 배포 절차

1. 합성 벡터로 오래된 관련 기록의 검색, 키워드 대체 경로, 모델 불일치 및 최신성 규칙을 검증한다.
2. 실제 SQL의 사용자·상대 분리, 잘못된 벡터 거절, 제외·잊기·복원·동시 쓰기를 검증한다.
3. 서버 테스트에서 모델 역할, 예산·캐시, 검색 실패 대체, 기억 버전 변경 시 오래된 체크포인트 배제를 확인한다.
4. 브라우저에서 사실 편집·잊기·회차 제외/복원, 통화 중 제한, 오류 처리, 모바일 및 배포용 CSP를 확인한다.
5. 전체 검사 통과 후 배포하고 DB 마이그레이션과 공개 사이트의 새 코드를 확인한다. 실제 승인 계정의 음성·의미 검색 품질과 합성 테스트 결과를 구분해 보고한다.

합성 벡터의 통과율은 실제 임베딩 모델이 한국어·영어 표현의 의미를 올바르게 이해한다는 측정치가 아니다. 실제 대화 품질 평가는 승인 계정의 별도 표본이 필요하다.

## 실행 상태

이번 범위의 코드와 평가를 구현했다. 타입 검사, 통합 검사 69개와 추가 회귀 검사 1개, SQL 합성 평가 10개, 브라우저 회귀 검사 및 설정 포함 빌드가 통과했다. 배포 전 CI에 같은 검증을 추가했다. 실제 모델 의미 품질과 실제 다중 연결 부하 검증은 별도 범위로 남긴다.
