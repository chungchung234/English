# 전화 영어 목적에 맞춘 페르소나와 시간 및 기억 고도화

기준일: 2026-11-11 KST. 시시콜콜의 전화 영어 목표를 **자기 뜻을 영어로 전달하고, 상대 말을 듣고 반응하며, 이해가 막히면 복구하고, 대화를 스스로 이어가거나 끝내는 능력**으로 둔다. 사용자는 자유롭게 대화할 수 있고, 필요할 때 표현·문법 도움을 받는다. 기존 시각 디자인과 종료 직후 대화문·선택 복습 흐름을 유지하면서 페르소나, 시간 문맥, 이전 대화의 연속성을 개선한다.

## 연구가 지지하는 방향

| 판단 | 핵심 근거 | 제품 적용 범위 |
| --- | --- | --- |

| 의미 있는 결과와 사용자 산출 기회를 함께 확보한다 | [Loewen & Sato 2018](https://doi.org/10.1017/S0261444818000125), 상호작용 종합 검토 | 정보 요청·선택·합의·이유 설명을 지원한다. 정답 문장 복창이나 질문 수를 성공으로 삼지 않는다 |

| 교정 뒤 재표현·지연 유지·새 상황 사용은 다른 결과다 | [Li, Li & Qian 2026](https://doi.org/10.1111/lang.70019), [Kim & Webb 2022](https://doi.org/10.1111/lang.12479), [Suzuki & Hanzawa 2022](https://doi.org/10.1017/S0272263121000358) | 기존 답 가림·선택 도움·지연 회상은 유지한다. 읽음·따라 말함·한 번의 사용을 숙달로 승격하지 않는다 |
| 시간 추론·정보 갱신·근거 없을 때 답하지 않기를 따로 확인해야 한다 | [LongMemEval, ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d813d324dbf0598bbdc9c8e79740ed01-Abstract-Conference.html), 공식 초록 확인 | 검색 성공과 응답에서의 적절한 사용을 구분한다. 원통화 시점과 사실 수정·잊기를 보존한다. 이 앱의 기억 품질 향상률로 논문 수치를 환산하지 않는다 |

전화·음성 매체 연구, 교정 시점의 반례, ASR의 오류 정규화 문제와 각 자료의 전문/초록 접근 범위는 [전화 영어 목적](research/phone-english-purpose.md), [페르소나 연구](research/phone-english-personas.md), [학습 구조와 평가](research/phone-english-learning-evaluation.md)에 정리했다. 중복 연구의 참가자 수는 합산하지 않는다.

## 페르소나와 답변 방식

통화에서는 영어로 의미를 주고받는 AI 대화 상대를 기본 역할로 둔다. 사후 분석은 근거에 기반한 코칭 역할을 맡는다. 통화 중에도 사용자가 요청한 표현·문법 설명과 이해 복구는 바로 지원한다. 이 역할 분리는 현재의 코치·대화 상대 지침 혼합을 정리하는 설계 판단이며, 특정 단어를 바꾸면 학습효과가 향상된다는 실험 결과가 아니다.

목적·언어·발언권·기억 보호는 모든 캐릭터가 공유한다. 성격은 반응의 초점과 말투에 차이를 주며, 캐릭터를 초급·중급·고급 등급이나 도움의 양과 고정 연결하지 않는다.

| 캐릭터 | 반응의 중심 | 멈추는 기준과 피할 행동 |
| --- | --- | --- |
| Mia | 사용자가 직접 말한 구체적 경험과 감정에 차분히 반응 | 충분히 받아줬으면 멈춘다. 긴 위로·과한 칭찬·감정 진단을 붙이지 않는다 |
| Alex | 상황에 대한 구체적인 관찰과 필요한 정보 | 요청에 답했으면 멈춘다. 요청하지 않은 조언·체크리스트·교훈으로 바꾸지 않는다 |
| Juno | 사용자가 말한 내용에 연결된 쉬운 상상과 가벼운 유머 | 짧은 반응 뒤 발언권을 돌려준다. 매번 농담·새 질문을 만들거나 실수·어려움을 놀리지 않는다 |

작성한 예시로 “I cooked without a recipe today. I'm proud.”에 Mia는 “You made it your own. That sounds satisfying.”, Alex는 “You figured out the dish yourself.”, Juno는 “The recipe got a day off.”처럼 질문 없이 반응할 수 있다. 이 예시는 실제 모델 출력이 아니다. “퇴근 후 산책했어를 영어로?”에는 세 캐릭터 모두 “I went for a walk after work.”처럼 필요한 표현을 직접 줄 수 있다. 매 턴 성격 차이를 과시할 필요는 없다.

| 사용자 상황 | 공통 대화 정책 |
| --- | --- |
| 일상 경험 공유 | 마지막 구체적 내용에 짧게 반응하고 발언권 반환. 후속 질문은 필요한 경우에만 |
| 사실·뜻·표현 질문 | 직접 답부터 제공. 요청하지 않은 강의·반복 과제를 추가하지 않음 |
| 자세히 설명해 달라는 요청 | 필요한 내용을 작은 단위로 설명. 단어 수 때문에 의미를 생략하지 않음 |
| 못 들음·이해 실패·오해 | 문제 부분을 좁혀 반복·쉬운 말·짧은 예로 복구. “yes”만으로 이해를 확정하지 않음 |
| 생각 중·도움 거절·주제 전환 | 요청을 존중하고 힌트·조언·새 질문으로 덮지 않음 |
| 이해 가능한 작은 오류 | 발화 중간을 끊지 않고 자연스러운 구간이나 선택한 사후 복습에서 다룸 |
| 한국어·혼합 언어 입력 | 뜻을 이해하고 쉬운 영어로 응답. 한국어 자체를 문법 오류로 분류하거나 비난하지 않음 |

역할·예시·언어·흐름을 구분하고 충돌을 줄이는 구성은 [OpenAI Realtime 공식 프롬프팅 안내](https://developers.openai.com/cookbook/examples/realtime_prompting_guide)와도 일치한다. 공식 예시의 2~3문장 같은 수치는 고객지원 예시이며 전화 영어의 보편적 최적값으로 채택하지 않는다.

## 현재 시각과 저장 시각

시각에는 세 가지 의미가 있다. 화면의 현재 시각, 통화 기록의 생성·종료 시각, 각 발화를 수신해 기록한 시각이다. 기존 경과 시간 타이머는 이와 별개로 유지한다.

새 통화는 UTC 시점과 기기에서 확인한 IANA 시간대 이름을 함께 저장한다. 화면은 서버가 전달한 시각을 기준으로 경과한 시간을 더해 현재 시각을 표시하며, 기기 시계가 잘못 설정됐다고 과거 기록을 덮어쓰지 않는다. 시간대는 위치나 생활 습관의 증거가 아니다. 서울 시간대라는 이유로 날씨·출근·식사·취침을 추정하지 않는다.

모델에는 통화 시작과 통화 문맥 갱신 때의 기준 시각·시간대·현지 날짜를 전달한다. 시간대에 맞는 짧은 인사나 질문은 가능하지만 현재 주제보다 우선하지 않는다. **화면 시계는 계속 움직이고, 모델의 시간 정보는 마지막 지침 갱신 시점의 스냅샷**이다. 모델이 계속 정확한 현재 시각을 관측한다고 말하지 않으며, 정확한 시각 질문에는 마지막으로 확인한 시점이라는 범위를 보존한다. 오래된 기준 시각이나 알 수 없는 원통화 시간대에서 ‘오늘·어제·내일’을 확정하지 않는다.

`timestamptz`는 UTC 순간을 보존하지만 입력 당시의 시간대 이름을 보존하지 않는다. 따라서 `sessions.time_zone`을 별도로 둔다. [PostgreSQL 공식 설명](https://www.postgresql.org/docs/current/datatype-datetime.html#DATATYPE-DATETIME-INPUT-TIMESTAMPS)

- 이전 기록의 시간대는 `null`로 유지한다. 현재 기기 시간대를 과거 통화 당시의 값으로 소급 기록하지 않는다.
- `sessions.created_at`은 통화 기록 생성 시각이다. 실제 연결 확인은 기존 연결 사건과 구분한다.
- 발화의 `timestamp`는 수신 기록 시각이다. 실제 음성 시작·종료의 정밀 측정으로 표시하지 않는다.
- 기록 상세·통화 후 대화문에서 시각을 확인할 수 있게 하고, 재접속·백업·복원에서도 UTC 시점과 저장 시간대를 보존한다.
- 시간대가 없는 과거 기록에는 표시 기준 시간대와 당시 정보가 없다는 점을 구분한다. 복원으로 이미 저장된 시간대가 몰래 바뀌지 않게 한다.

## 이전 대화가 이어지는 경험

코드 점검에서 사실의 `spoken_at`·근거 인용·수동 수정 여부가 음성 지침을 구성할 때 빠지고, 기억의 날짜는 원통화 시각 대신 분석 생성 시각으로 전달되는 문제가 확인됐다. 기본 검색어와 첫 인사도 일반적인 일상 대화로 고정돼 있었다. 운영 기록의 보류 사유 점검에서는 현재 제외·보류가 원인이라는 근거가 나오지 않았다. 실제 모델이 기억을 어떤 방식으로 사용했는지는 별도의 음성 관찰이 필요하다.

이번 변경은 다음 경로를 연결한다.

1. **기억 검색:** 일반 통화는 실제 원통화 날짜에 따른 최근 기록을 기본으로 삼는다. 통화 문맥을 갱신할 때는 최근 사용자 발화를 검색 단서로 사용할 수 있다. 의미·키워드 검색과 기존 상한은 유지한다.
2. **시간과 근거 전달:** 원통화의 생성·종료 시각과 시간대, 같은 계정·캐릭터·통화의 실제 사용자 근거 발화를 함께 전달한다. 나중에 분석을 다시 만들었다고 오래된 통화가 최신 통화가 되지 않는다.
3. **자연스러운 이어가기:** 관련 있는 최근 이야기가 있으면 짧게 연결한다. 이미 사용자가 새 주제를 꺼냈거나 준비한 이야기가 있으면 그것을 우선한다. 매번 기억 목록을 읽거나 기억을 과시하지 않는다.
4. **계획과 사실 구분:** “내일 산책할까 해”는 계획이다. 다음 통화에서 산책했다고 단정하지 않고, 그 이야기를 이어갈 수 있는지 확인한다. 수동 수정한 사실을 지난 통화에서 들었다고 말하지 않는다.
5. **준비 상태 표시:** 실제로 모델에 전달한 문맥을 기준으로 기억 준비됨·보류·없음을 구분한다. 준비된 기록 수를 모델이 실제 언급한 횟수로 표시하지 않는다.

기억 삭제·제외·보류·잊기 표식, 사실 수정 우선순위, 계정·캐릭터 분리, 전송 직전의 버전 재검사를 유지한다. 기억이 있다는 느낌을 만들기 위해 없는 공동 경험을 꾸미거나 보류된 원문을 우회해 가져오지 않는다. 과거 대화가 아직 유효한 분석으로 정리되지 않았다면 기억 범위에 포함되지 않을 수 있다.

## 복습과 성과 확인

기존의 종료 직후 대화문 → 선택한 교정 → 자기 말로 재표현 → 답을 가린 지연 회상 → 다음 통화의 사용 기회를 유지한다. 자유대화 진입에 과제 선택이나 숙제를 의무화하지 않는다. 경험 설명·조건 비교·약속 조정·되묻기처럼 사용자가 원하는 작은 의사소통 목표를 대화 지침에서 지원한다.

소프트웨어 검사와 별도로 확인할 성과는 의도 전달, 듣고 적절히 반응, 이해 실패 복구, 주제·질문·거절·종료에 대한 주도권, 도움 없이 다시 쓰기다. 통화 시간·단어 수·표현 출현·만족도를 영어 실력 점수로 합치지 않는다. ASR가 문법 오류를 올바른 문장으로 전사할 수 있으므로 전사문의 오류 감소를 실제 발화 향상으로 판정하지 않는다.

실제 모델 비교에서는 모델·목소리·속도·VAD·기억·입력을 고정하고 행동 지침만 바꾼다. 현재 캐릭터는 목소리도 다르므로 세 캐릭터의 선호 차이를 페르소나 문구의 효과로 단정할 수 없다. 이후 실제 캐릭터 조합의 사용성을 확인한다. 참여자 6~8명 관찰은 실패 발견을 위한 형성평가이며 장기 학습효과 입증이 아니다. 참여자 자료가 없는 상태를 자동 테스트로 채워 완료 처리하지 않는다.

## 이번 배포 범위와 확인 기준

이번 배포는 페르소나와 공통 전화 영어 행동, 시간 문맥·저장·표시, 근거와 시점을 보존하는 이전 대화 연결을 포함한다. 기존 발언권 제어·간결한 영어 응답·종료 직후 대화문·회상·저장 보호를 회귀 검사한다. 새로운 음성 원본 수집, 자동 능력 등급, 과제 선택을 강제하는 화면은 추가하지 않는다.
