# E01~E05 고도화 구현·검증 결과

작성일: 2026-11-10 KST. 요구사항은 [기획안 13절](post-call-plan.md#13-실제-통화-검증-이후-고도화-우선순위), 실제 평가 절차는 [평가 프로토콜](enhancement-evaluation-protocol.md)에 기록한다.

**E01~E05의 기능과 자동 인수를 구현했다. 실제 참여자·사람의 품질 검토·기간 관찰은 미완료다.** 사용자가 현재 참여자와 검토 자료가 없음을 확인했으므로, 합성 검사나 자기보고로 실제 학습효과를 대신 판정하지 않았다.

## 구현한 기능

| 결정 | 구현 결과 | 아직 필요한 실제 증거 |
| --- | --- | --- |
| E01 측정 신뢰성 | CI 커밋 또는 실제 소스 해시로 클라이언트 버전 식별. 신규 회차에 변경 불가 버전, 사건에 허용된 버전·스키마 정보만 저장. 실제 RTC 연결 후 동일 사건 ID로 기기 저장 재시도, 기기 저장 확인 뒤 완료 표시. 생성·기기 저장·서버 확인 진단 분리 | 최신 배포 페이지에서 실제 음성 연결·오프라인·재접속의 운영 사건 대조. 과거 누락 사건은 생성하지 않음 |
| E02 교정 이의 해결 | 의도 설명을 원래 녹취와 분리해 저장. 원본 근거·버전과 AI 제안을 검증하고 사용자가 수락/닫기. 기존 보류·원문·분석 유지. 같은 분석의 다른 출처와 충돌하는 제안은 자동 병합하지 않음 | 사람의 교정 적절성·이의 해결·재발 표본 검토 |
| E03 개인별 지연 복습 | 목표·반복 출처·선택 상태를 추천에 반영. 선택형 1·3·7일 KST 회상, 어려움/도움/독립 수행 자기보고. 즉시 수행과 지연 회상 구분, 기본1개·명시적 추가 최대3개 유지 | 실제 1·3·7일 회상 결과, 추천 적합성과 학습 부담 관찰 |
| E04 다음 통화 활용 | 서버가 실제 음성 문맥에 준비한 목표만 해당 회차에 연결. 실제 사용자 발화의 표현 출현·근거를 관찰하고 자기 확인. 원문 변경·제외·보류 시 노출과 문맥 사용 차단 | 사용할 기회·적절한 활용·반복/힌트/새 상황의 사람 라벨. 자동 성공·숙달 판단은 활성화하지 않음 |
| E05 주간 행동 계획 | 정확한168시간 근거로 계속/새 목표 제안. 명시적 선택·다음 통화 준비·첫 유효 연결·그 뒤 지연 회상을 연결. 이후 통화나 늦은 사건이 기존 연결을 덮지 않음 | 실제 목표 선택→다음 통화→지연 회상과 성숙한 재방문·부담 지표 |

추가 행동은 기존 복습·최근 통화·계정의 펼침 영역과 인라인 연습에 연결했다. 승인된 화면 구조·이미지·모션과 스타일을 유지하고, 추가 설명 입력창에는 기존 입력 필드의 글꼴·색·테두리 규칙을 재사용했다. 동시 진행된 최신 메인의 로그인 전환·캐릭터 알파 정리·넓은 스와이프도 통합했다.

## 자동 검증과 범위

- 구문·Deno 타입 검사, DB·서버·대기열·평가·배포 패키징 검사 통과. 최종 실행 수치와 게시 버전은 해당 커밋의 [CI](https://github.com/chungchung234/English/actions)로 확인한다.
- 실제 Chromium·IndexedDB·인증 역할·PGlite SQL/RLS로 기존16개 + 통화 후16개 + 고도화6개, 총38개 브라우저 그룹을 확인했다. 최신 디자인 통합 후 느린 스와이프·버튼 드래그 방지와 캐릭터 알파·오디오·대체 렌더링5개도 재실행해 총43개 그룹이 통과했다.
- E01은 첫 기기 저장 실패 후 추가 RTC 사건 없이 재시도, 동일 UUID·발생 시각, SDP만 성공한 부정 사례, 오프라인·새로고침·중복 제거를 검사했다.
- E02는 보류 중 자동 추천 금지, 수락/닫기 CAS, 원문·분석 바이트 보존, 다른 소유자·오래된 출처·승인 취소·동일 표현의 출처 충돌을 검사했다.
- E03은 KST 자정의1·3·7일 경계, 미도래 회상 거부, 기존 수행과 별도 자기보고, 추천 상한과 가린 회상을 검사했다.
- E04는 학습 문맥 생략 시 목표를 사후 생성하지 않음, 같은 회차·화자 근거, 보류·제외·원문 변경 차단, 자동 성과 표시 없음, 자기 확인을 검사했다.
- E05는168시간 범위·버전·소유권, 첫 목표 선택 경합, 선택→준비→통화A→회상R→통화B 및 늦은 사건 도착에서 A+R 유지, 백업의 신뢰 상태 미승계를 검사했다.
- `eval:memory`는 합성 벡터·실제 SQL의 검색·격리10개를 확인한다. `eval:learning`은 고정 합성 문장14개를 확인하며 `human_quality_measured=false`, 참여자 수 미측정, `production_gate=observational_only`를 출력한다.

브라우저의 외부 인증·모델·WebRTC 전송은 명시적 테스트 응답이다. 실제 SQL·브라우저 동작과 실제 운영 음성·영어 해석 품질을 구분한다. 이전 [실제 Alex 통화](live-voice-acceptance-20261110.md)는 기반 흐름의 증거이며, 이번 확장 기능의 실제 품질 평가로 재사용하지 않는다.

## 출처·개인정보·비용

새 상태는 마이그레이션 `202611100013`~`202611100015`로 추가한다. 기존 학습 API와 v1/v2 백업을 유지하며 확장 백업에는 자기보고·설명·일정·목표와 과거 상태를 포함한다. 가져온 AI 결과와 출처는 신뢰된 제안으로 활성화하지 않고 보관·재검증 상태로 유지한다.

독립 검토에서 발견한 제안의 출처 충돌, 주간 목표 첫 선택 경합·회상 연결 덮어쓰기, 보류된 실제 회차의 활용 근거, 자동 사실의 보류·제외 출처와 오래된 분석으로의 후퇴를 보완했다. 수동 사실·잊기와 기존 구조화 사실의 cutoff 정책은 유지한다. 학습 문맥을 생략한 통화·체크포인트는 오래된 학습 상황도 보내지 않는다.

AI 재검토는 기존 서버 키·교정 모델·추론 정책과 공유 텍스트 예약 예산을 사용한다. 재검토 요청은 사용자당 UTC 일10회이며 실패 재시도도 한도를 사용한다. E04 표현 관찰은 생성 모델을 추가 호출하지 않는다. 요청형 주간 분석은 기존 일3회·공유 비용 예산을 유지하며 학습 상태가 달라지면 캐시가 갱신될 수 있다. 사용량이 불명확하면 비용0으로 표시하지 않는다.

## 배포 전 데이터 보호

마이그레이션013~015 적용 전에 기존 운영22개 public 테이블·52행과 적용된10개 마이그레이션을 암호화해 별도 사본으로 보관했다. 키는 분리했고 평문 데이터 파일은 만들지 않았다. 격리 복원49개 검사에서 전체 행·스키마·참조·소유권·승인 검증이 통과했다. 이는 데이터가 있는 수동 논리 복원 증거이며 관리형 자동 백업·인증 서비스·물리 복구를 포함한 전체 DR을 뜻하지 않는다.

## 완료 판단

기능·자동 인수와 실제 품질·효과 게이트를 각각 관리한다. 기획안 전체의 평가 기준을 완료하려면 실제 참여자6~8명과 사람의 검토, 1·3·7일 지연 회상·7일 재방문 및 관찰창·전송 유예를 충족한 자료가 필요하다. 현재 이 자료가 없어 **실제 평가 게이트는 대기**다. 자동 검증을 근거로 이 항목을 완료 처리하지 않는다.
