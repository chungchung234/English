# 직전 통화 기억 경로 보완

이 문서는 최초 복구 조치의 기록이다. 현재 구현은 [독립 대화 기억과 제한된 재처리](conversation-memory-and-recovery-20261111.md)로 개선했으며 아래의 원문 12개 상시 전달 방식은 대체했다.

기존 통화 기억은 분석 결과에 의존했다. 원문이 저장돼도 분석이 실패하면 해당 회차는 다음 통화의 검색 결과에서 빠졌다. 또한 통화 연결 작업에는 실제로 구성한 기억의 출처를 남기지 않아 당시 전달 여부와 모델의 활용 여부를 구분하기 어려웠다.

`202611110002_recent_conversation.sql`은 같은 사용자·캐릭터의 가장 최근 종료 통화 중 사용자 발화가 있는 회차를 찾아 원문 최대 12개를 제공한다. 종료만 누른 무발화 회차, 미완료·부분 기록, 제외·잊기 이전 기록, 품질 보류 및 제외 표현이 연결된 회차는 사용할 수 없다. 기존 `suppress_memory` 정책이 켜진 경우 이 경로도 생략한다. 분석 실패를 성공으로 바꾸거나 승인·제외 정책을 완화하지 않는다.

음성 함수는 이 자료를 `memory.recent_conversation`으로 전달한다. 각 원문은 최대 500자, 전체 묶음은 8,000바이트 이하이며 가장 최근 사용자 발화가 포함된 상태만 사용한다. 기존 20,000바이트 문맥 한도에서 오래된 검색 요약을 먼저 덜어내고 직전 통화와 사실 프로필을 유지한다. 요약이 있으면 최대 1,000자를 함께 전달한다. 전체 이력의 완전 회상을 보장하지 않는다.

현재 발언과 직접 수정·잊기 표시가 우선이다. 과거 AI 발언은 사용자 사실의 근거가 아니며, 일부 원문만 전달된 상태에서 없는 세부를 만들어내지 않도록 지시한다. 통화 시작의 continuity는 직전 통화의 실제 사용자 발화 ID와 날짜를 우선한다.

통화 연결 작업의 `analysis_jobs.result`에는 최종 문맥의 기억 건수·출처 세션 ID·원문 발화 수·직전 분석 상태·지침 SHA-256을 기록한다. 원문·요약·사용자 사실·SDP·키는 이 진단 기록에 복사하지 않는다. 이 기록은 제공자에게 보낸 문맥의 증거이며, 모델이 기억을 정확히 활용했다는 증거와는 구분한다. 기존 화면은 변경하지 않는다.

검증은 실제 PostgreSQL 엔진의 합성 계정·세 캐릭터로 분석 실패 후 원문 복구, 무발화 회차 건너뛰기, 계정·상대 격리, 제외·잊기·품질 보류·부분 기록·승인 철회와 서비스 전용 권한을 확인한다. 음성 API 요청 본문의 근거와 저장되는 전달 기록도 검사한다. 실제 승인 계정의 기억 회상 품질은 별도 음성 확인 대상이다.
