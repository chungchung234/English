# 대화 페르소나와 브라우저 마이크 입력 처리 적용

2026년 11월 12일 KST. 사용자가 확인한 공통 지침과 Mia·Alex·Juno 페르소나를 영문 통화 지침에 반영하고, 브라우저 마이크의 소음 중단을 줄이기 위한 입력 필터와 진단을 추가한다.

## 적용 동작

캐릭터가 사용자의 구체적인 내용에 관점·관찰·관련 지식·선택적 유머를 보태도록 바꿨다. 공감 뒤 질문이나 도움 메뉴로 돌아가는 반복을 줄이고, 주제를 골라 달라는 요청에는 실제 주제를 골라 이어가도록 한다. 통화 안의 길이·교정·질문·주제 전환 요청을 반영하며, 앱 불편을 문법 교정으로 바꾸지 않는다. 영어 응답·혼합 언어 이해·근거 있는 기억·AI 정체성 경계는 유지한다.

Mia는 작은 세부를 차분히 받아주고, Alex는 관점과 비교를 보태며, Juno는 관련 있는 연상과 유머를 선택적으로 사용한다. 세 캐릭터의 카페·요리 예시는 행동 참고이며 반복 대사나 사용자 기억이 아니다. 과거 학습 표현 `memory.focus`만으로 연습을 권하는 지시를 제거했고, 사용자가 준비한 목표가 있을 때만 선택적 기회를 제공한다. 사용자가 이미 말했거나 응답이 진행 중이면 별도 시작 요청을 보내지 않으며, 기본 지침도 사용자 선발화와 진행 중 주제를 우선한다.

브라우저가 허용한 마이크를 그대로 사용하고 에코 제거·소음 억제 요청과 공급자 입력 필터를 적용한다. 앱에 실제 전화의 스피커폰 모드나 오디오 경로 전환 기능은 없다. 잘못 추가한 스피커폰/이어폰 선택 UI와 브라우저별 선택 저장·읽기·전송을 제거했다. 새 클라이언트는 마이크 종류를 추측하지 않으며 서버는 사용 환경을 `unknown`으로 기록한다. 기존 `far_field` 기본 필터와 semantic VAD low·자동 끼어들기·속도·전사 모델은 유지한다. 이는 브라우저가 실제 장치나 마이크 거리를 자동 감지했다는 의미가 아니다.

이미 열려 있는 구형 클라이언트의 명시적 `speakerphone`·`headset` 값만 호환 목적으로 계속 받는다. 새 화면에서는 이 값을 선택하거나 전송하지 않고, 과거 저장값도 새 요청에 사용하지 않는다.

공급자가 정확히 해당 선택 필드의 미지원을 400 오류로 확인한 경우에만 한 번 필터 필드를 생략해 호환 연결을 시도한다. 불명확한 오류·값 오류·인증·한도·서버 오류는 재시도하지 않는다. 호환 경로에서도 기억·준비 목표의 revision을 재검증하며, 공급자 기본 설정을 필터 적용 성공으로 기록하지 않는다.

음성이 계속 재생 중이면 단순 `speech_started`만으로 캐릭터 표시를 듣는 상태로 바꾸지 않는다. 실제 출력 중단 이벤트와 생성 완료를 구분한다.

## 관측과 데이터 경계

`call_diagnostics`에 정보용 `audio_configuration`, `audio_interruption`과 제한된 `audio_context`를 추가한다. AEC·NS·AGC의 보고 값, 요청한 사용 환경, 공급자가 확인한 실제 필터·VAD, 출력 상태와 취소 출처만 받는다. 필드가 없으면 미확인으로 남기고 설정값을 실제 음향 효과로 해석하지 않는다.

`response.done.status_details.reason=turn_detected`는 공급자가 발화 감지로 취소했다는 의미다. 실제 사용자 발화였는지 소음이었는지는 증명하지 않는다. `client_cancelled`는 해당 응답의 로컬 요청과 연결할 수 있을 때만 종료·멈춤·기타로 나눈다. 알 수 없으면 원인 미상으로 둔다. 응답 연결에는 브라우저가 만든 임의 UUID를 사용하고 공급자 응답 ID를 저장하지 않는다.

원음·전사·provider message·SDP·장치 ID·이름은 진단에 넣지 않는다. 서버의 엄격한 enum·소유권·승인 계정·ACK·중복 요청 검증을 유지한다. 기존 필드만 보내는 구형 앱도 계속 받는다. 진단 실패는 통화·저장 상태를 바꾸지 않는다. 큐 100개·배치 20개·세션 200개와 전송 누락 가능성이 있으므로 행 수를 전체 중단 발생률로 해석하지 않는다.

통화 정책 버전은 `2026-11-12-reciprocal-companion-v1`, 음성 입력 정책은 초기 `2026-11-12-speakerphone-v1`에서 정정된 `2026-11-12-browser-microphone-v2`로 구분한다. 추가 DB migration은 `202611120001_call_audio_diagnostics`다. 이전 배포 migration은 수정하지 않는다.

## 검증과 배포 기록

기준 변경 커밋은 `1ebe0f0`이다. `npm run check`, 단위·DB 검사 332개, 설정을 포함한 빌드, 합성 기억 10개·표현 관찰 14개를 통과했다. 신규 `call-audio` 브라우저 검사는 기본 스피커폰·이어폰 선택의 키보드 조작·계정별 저장·재접속·효과 설정과 취소 원인 기록을 확인했다. 기존 presence·10분 신뢰성 브라우저 검사도 통과했다.

[390px 설정](design/companion-audio-20261112/settings-390.png)과 [320px 큰 글자 설정](design/companion-audio-20261112/settings-320.png)을 실제로 열어 라디오·문구·초점·스크롤과 넘침을 확인했다. 인증·공급자 음성·API는 fixture다. 이 검사를 실제 휴대폰 소음 억제나 친구 같은 대화 품질의 검증으로 보고하지 않는다. 기존 주요 브라우저 회귀도 통과했다.

이번 적용은 페르소나·대화 정책·마이크 환경 선택·필터·설정/취소 관측이다. [전체 설계](quality-and-opening-design-20261112.md)의 영속 오프닝 계획·공통 근거 보류 v2·실시간 비용 관측·앱이 발화를 판별해 중단하는 후속 제어는 별도 구현 범위다. 실제 휴대폰에서는 작은 잡음의 오중단과 조용한 실제 발화·짧은 중단 요청의 보존을 함께 비교해야 한다.


## 첫 배포 확인

[PR 15](https://github.com/chungchung234/English/pull/15)를 병합한 앱 커밋은 `8cea9e488f0cb43e7f36ec55cf8d99ec618db236`이다. [배포 실행](https://github.com/chungchung234/English/actions/runs/43154867629)의 전체 검사·DB/함수·Pages 배포·배포 후 access/voice 경로 검사가 성공했다. 공개 사이트의 `LOOP_CLIENT_BUILD`가 `git:8cea9e488f0cb43e7f36ec55cf8d99ec618db236`과 일치하고, 새 설정 HTML과 `assets/app.185377966118.js`가 반영됐다. 이 기록을 보완한 후속 문서 커밋은 앱 동작을 바꾸지 않는다.

운영 DB에서 신규 migration 체크섬·JSONB 제약·RLS·승인 계정 권한을 확인했다. 실제 배포된 coach 본문에서 두 정책 버전·모드별 필터·제한된 fallback이 모두 확인됐다. 승인 계정의 authenticated 역할로 기존/신규 진단 ACK·멱등 재시도·잘못된 context 거부를 검증한 뒤 트랜잭션 전체를 롤백했으며 임시 통화와 진단이 남지 않았다. 실제 계정 식별자·메일·원문·토큰은 검증 출력에 포함하지 않았다.

공개 사이트의 HTML과 배포 번들을 그대로 읽는 브라우저 검사에서도 마이크 설정·재접속·계정 격리·진단·발화 감지 시 표시 동작이 통과했다. [공개 390px](design/companion-audio-20261112/live-settings-390.png)과 [공개 320px 큰 글자](design/companion-audio-20261112/live-settings-320.png)는 인증·공급자/API를 모의 처리한 화면이며, 실제 승인 계정의 통화나 휴대폰 음향 효과 검증은 아니다.


## 브라우저 마이크 설정 정정

사용자가 확인한 제품은 브라우저 마이크 입력이며 별도 전화 모드가 없다. 입력 필터를 고르는 옵션을 실제 사용 모드처럼 노출한 것은 부정확했으므로 선택 UI·선호 저장·새 요청의 모드 전송을 제거했다. 마이크 권한과 입력 장치 선택은 브라우저/운영체제의 기존 동작을 따른다. 신규 요청의 `requested_microphone_mode`는 `unknown`이며, 적용된 소음 필터·AEC/NS 보고값과 취소 원인만 기존 진단에서 계속 확인한다. 출력 경로·장치 종류를 자동 감지했다는 표시를 만들지 않는다.

정정 코드의 타입·구문 검사와 설정을 포함한 빌드, 관련 서버 검사 85개·오디오 관측/진단 검사 21개가 통과했다. 개정 브라우저 검사는 모드 선택 UI가 없고, 과거 저장값을 읽지 않으며, 새 voice 요청에 `microphoneMode`를 보내지 않는 것을 확인했다. 환경 미확인·실효 필터 관측·중단 원인·두 계정의 진단 소유권도 확인했다.
