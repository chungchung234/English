# 대화 페르소나와 스피커폰 입력 처리 적용

2026년 11월 12일 KST. 사용자가 확인한 공통 지침과 Mia·Alex·Juno 페르소나를 영문 통화 지침에 반영하고, 휴대폰 스피커폰의 소음 중단을 줄이기 위한 입력 필터와 진단을 추가한다.

## 적용 동작

캐릭터가 사용자의 구체적인 내용에 관점·관찰·관련 지식·선택적 유머를 보태도록 바꿨다. 공감 뒤 질문이나 도움 메뉴로 돌아가는 반복을 줄이고, 주제를 골라 달라는 요청에는 실제 주제를 골라 이어가도록 한다. 통화 안의 길이·교정·질문·주제 전환 요청을 반영하며, 앱 불편을 문법 교정으로 바꾸지 않는다. 영어 응답·혼합 언어 이해·근거 있는 기억·AI 정체성 경계는 유지한다.

Mia는 작은 세부를 차분히 받아주고, Alex는 관점과 비교를 보태며, Juno는 관련 있는 연상과 유머를 선택적으로 사용한다. 세 캐릭터의 카페·요리 예시는 행동 참고이며 반복 대사나 사용자 기억이 아니다. 과거 학습 표현 `memory.focus`만으로 연습을 권하는 지시를 제거했고, 사용자가 준비한 목표가 있을 때만 선택적 기회를 제공한다. 사용자가 이미 말했거나 응답이 진행 중이면 별도 시작 요청을 보내지 않으며, 기본 지침도 사용자 선발화와 진행 중 주제를 우선한다.

내 계정의 마이크 사용 환경에서 스피커폰과 이어폰·헤드셋을 선택한다. 기본은 스피커폰이다. 선택은 이 브라우저의 계정별로 기억하며 다음 통화에 적용한다. 실제 오디오 출력 경로를 자동 검증했다는 의미는 아니다. 스피커폰은 `far_field`, 이어폰은 `near_field`를 공급자 입력 필터에 전달한다. 브라우저의 AEC·NS 요청과 기존 semantic VAD low·자동 끼어들기·속도·전사 모델은 유지한다. 마이크를 끄거나 모든 끼어들기를 막지 않는다.

공급자가 정확히 해당 선택 필드의 미지원을 400 오류로 확인한 경우에만 한 번 필터 필드를 생략해 호환 연결을 시도한다. 불명확한 오류·값 오류·인증·한도·서버 오류는 재시도하지 않는다. 호환 경로에서도 기억·준비 목표의 revision을 재검증하며, 공급자 기본 설정을 필터 적용 성공으로 기록하지 않는다.

음성이 계속 재생 중이면 단순 `speech_started`만으로 캐릭터 표시를 듣는 상태로 바꾸지 않는다. 실제 출력 중단 이벤트와 생성 완료를 구분한다.

## 관측과 데이터 경계

`call_diagnostics`에 정보용 `audio_configuration`, `audio_interruption`과 제한된 `audio_context`를 추가한다. AEC·NS·AGC의 보고 값, 요청한 사용 환경, 공급자가 확인한 실제 필터·VAD, 출력 상태와 취소 출처만 받는다. 필드가 없으면 미확인으로 남기고 설정값을 실제 음향 효과로 해석하지 않는다.

`response.done.status_details.reason=turn_detected`는 공급자가 발화 감지로 취소했다는 의미다. 실제 사용자 발화였는지 소음이었는지는 증명하지 않는다. `client_cancelled`는 해당 응답의 로컬 요청과 연결할 수 있을 때만 종료·멈춤·기타로 나눈다. 알 수 없으면 원인 미상으로 둔다. 응답 연결에는 브라우저가 만든 임의 UUID를 사용하고 공급자 응답 ID를 저장하지 않는다.

원음·전사·provider message·SDP·장치 ID·이름은 진단에 넣지 않는다. 서버의 엄격한 enum·소유권·승인 계정·ACK·중복 요청 검증을 유지한다. 기존 필드만 보내는 구형 앱도 계속 받는다. 진단 실패는 통화·저장 상태를 바꾸지 않는다. 큐 100개·배치 20개·세션 200개와 전송 누락 가능성이 있으므로 행 수를 전체 중단 발생률로 해석하지 않는다.

통화 정책 버전은 `2026-11-12-reciprocal-companion-v1`, 음성 입력 정책은 `2026-11-12-speakerphone-v1`이다. 추가 DB migration은 `202611120001_call_audio_diagnostics`다. 이전 배포 migration은 수정하지 않는다.

## 검증과 배포 기록

검증 결과와 실제 공개 빌드 식별자는 완료 후 기록한다. 자동 검사는 지침 전달, 설정·호환 경로, 출처 보호, 진단 권한, 저장·기존 통화 동작과 실제 화면 렌더링을 확인한다. 공급자 음성과 API를 대체한 fixture 검사를 실제 휴대폰 소음 억제나 친구 같은 대화 품질의 검증으로 보고하지 않는다.

이번 적용은 페르소나·대화 정책·마이크 환경 선택·필터·설정/취소 관측이다. [전체 설계](quality-and-opening-design-20261112.md)의 영속 오프닝 계획·공통 근거 보류 v2·실시간 비용 관측·앱이 발화를 판별해 중단하는 후속 제어는 별도 구현 범위다. 실제 휴대폰에서는 작은 잡음의 오중단과 조용한 실제 발화·짧은 중단 요청의 보존을 함께 비교해야 한다.
