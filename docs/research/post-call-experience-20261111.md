# 통화 이후 경험: 비판적 재검토와 개선 근거

2026-11-11 · 기존 감사에 대한 설계 검토 · 문헌 원문 확인

이번 개선의 목표는 보고서를 짧게 만드는 데 있지 않다. 통화를 마친 사용자가 **종료됐는지, 이번에 가져갈 표현은 무엇인지, 지금 무엇을 할 수 있는지**를 바로 이해하도록 하는 것이다. 표현을 한 번 연습하고 싶지 않은 사람도 자연스럽게 마칠 수 있어야 한다.

기존 [화면 감사](../design/post-call-audit-20261111/README.md)는 공개 프런트엔드와 합성 대화로 발견한 구조·상태 문제의 근거다. 아래 연구는 그 결과를 해석하고 개선안을 제한하는 자료다. 실제 사용자 연구, 한국인 AI 통화 학습 효과 실험, 포괄적인 문헌고찰을 수행한 것은 아니다.

## 1. 기존 판단에서 유지할 것과 수정할 것

| 판단 | 비판적 검토 | 이번 결정 |
| --- | --- | --- |
| 결과가 원문 아래 1,500px 이상으로 밀린다 | 한 합성 통화의 관측값이다. 모든 사용자 평균, 이탈률 또는 학습 실패를 입증하지 않는다. 그러나 준비 완료 뒤에도 첫 화면이 바뀌지 않는 문제와 경로별 순서 불일치는 직접 재현됐다. | 통화 길이에 영향을 덜 받는 결과 영역을 먼저 두고 원문은 명확한 이름으로 접는다. |
| 한 표현만 앞에 보여 주자 | 연구가 통화당 최적 표현 수를 1개로 정해 준 것은 아니다. 가장 중요한 내용의 인지를 돕는 제품 가설이다. 잘못된 표현 하나를 크게 보여 주면 오류의 권위도 커진다. | 근거 있는 교정·대안 중 하나를 우선한다. 근거가 부족하면 억지로 채우지 않으며 전체 내용·출처·보류 경로는 유지한다. |
| 내용은 첫 화면에 들어와야 한다 | 짧은 예시에는 좋은 설계 목표지만 긴 실제 문장, 큰 글자, 좁은 화면까지 모두 한 화면에 압축하면 읽기와 의미가 손상된다. WCAG도 한 화면에 전부 넣도록 요구하지 않는다. | 보통 길이의 표현과 주 행동을 위로 올린다. 긴 내용은 자연스럽게 세로로 늘어나게 하며 글자 축소·잘림·도크 가림으로 해결하지 않는다. |
| 설명과 선택지를 줄여야 한다 | 숨겨야 할 것은 부가 기능이다. 저장 실패, 사용자 발화 부재, 전사 불확실성, 연습이 자기 보고라는 사실은 사용자의 판단에 영향을 준다. | 중요한 예외는 해당 시점에 가까이 표시한다. 자세한 시스템 설명과 관리 기능만 뒤로 보낸다. |
| 연습 단계로 이어져야 한다 | 통화의 목적이 친교형 대화인 서비스에서 강제 숙제는 종료 경험을 악화시킬 수 있다. 직접 연습했다고 표시한 것은 실제 발화나 습득 증거가 아니다. | 연습은 분명한 선택지로 제공하고 마치기도 가능하게 한다. 저장 완료는 수행 표시의 저장이며 실력·발음 평가로 표현하지 않는다. |
| 단계마다 화면을 분리하면 명확해진다 | 과도한 단계 분리는 현재의 중첩된 조작 문제를 다른 형태로 반복한다. 원문과 제안을 비교하려는 사용자는 다시 오가게 된다. | 새로운 탭·긴 위저드 대신 같은 복습 영역에 회차 결과·연습·완료의 목적을 구분한다. 최초 표현 비교는 한곳에서 가능하게 한다. |

## 3. 사용자 과제에 맞춘 정보 순서

**통화를 끊었을 때 — “끝났고 내 말이 남았나?”**

상대와 종료 맥락을 보여 주고, 실제 확인 단계에 맞는 상태 하나를 둔다. 마이크 종료, 전사 수신, 클라우드 저장, 분석 생성은 내부적으로 분리된 상태지만 모든 내부 단계를 큰 문단으로 동시에 설명할 필요는 없다. ‘통화가 끝났어요’는 녹음·연결 종료를, ‘대화가 저장됐어요’는 서버 확인을 각각 사실대로 뜻해야 한다. 분석 실패가 이미 저장된 기록의 소실처럼 보이면 안 된다.

**결과가 준비됐을 때 — “무엇을 기억하면 되지?”**

해당 통화의 표현 하나를 가장 먼저 비교할 수 있게 한다. 원문, 다음에 사용할 문장, 짧은 이유가 하나의 읽기 덩어리가 된다. 구조화된 근거 없이 임의의 문법 제목을 새로 추정하지 않는다. 교정과 다른 표현 제안도 구분한다. 요약·잘한 점·추가 교정·전체 대화문은 결과의 위계를 보조하며 핵심 행동보다 먼저 긴 목록이 되지 않는다.

통화 직후와 특정 기록에서 연 회차는 같은 읽기 순서를 갖는다. 일반 복습 탭은 남겨둔 표현을 이어가기 위한 장소다. 방금 끝난 통화를 보는 동안 이전 피드백 목록과 주간 분석이 앞자리를 차지하지 않게 한다.

**연습을 선택했을 때 — “어떤 말을 직접 해 보면 되지?”**

표현에서 한 번의 조작으로 연습을 시작한다. 이미 답을 읽은 직후의 연습을 엄밀한 장기 기억 검사로 부르지 않는다. 짧은 단서와 도움 보기를 두고, 보여 준 답안의 다른 사본이 연습 화면에 남지 않게 한다. 녹음·평가가 없는 모드라면 버튼과 안내가 자동 발음 판정을 암시하지 않게 한다. 음성으로 말하기 어려운 상황에서는 나중에 이어갈 수 있다.

**저장이 확인됐을 때 — “여기서 마쳐도 되나?”**

이전 문제 지시·도움 보기·미루기·여러 홈 버튼을 남겨 두지 않는다. 자기 보고 연습의 저장 확인과 하나의 마치기 행동을 기본으로 둔다. 다음 통화 준비는 선택 행동이며 자동 마이크 연결이 아니다. 실패하면 완료 화면을 먼저 보여 주지 않고 현재 표현·의도를 보존해 다시 저장할 수 있게 한다.

## 4. 상태 표현의 우선순위

| 실제 조건 | 전면에서 이해해야 할 사실 | 피해야 할 충돌 |
| --- | --- | --- |
| 마지막 발화·서버 저장 미확인 | 통화는 끝났고 기록 확인이 진행 중 | ‘저장 완료’의 선표시, 완전히 준비된 결과처럼 보이는 가짜 성과 |
| 저장됨·분석 중 | 기록은 남았고 결과만 준비 중 | 원문 영역과 학습 영역이 서로 다른 준비 상태를 계속 표시 |
| 분석 완료 | 이번 결과와 선택 가능한 연습 | 준비 중 문구가 계속 남음, 다른 탭으로 이동한 사용자를 강제 복귀 |
| 사용자 발화 없음 | 이번 기록에서 표현을 정리할 근거가 없음 | 분석 중과 분석하지 않음의 동시 표시 |
| 저장됨·분석 실패 | 기록은 보존됐고 결과 생성은 다시 시도 가능 | 기록 소실처럼 보이는 일반 실패 토스트, 아래에 묻힌 복구 행동 |
| 일부 전사·전송 미확인 | 확인된 범위와 미완료 상태 | 전사 누락을 영어 실수로 평가, ‘간단히’ 만들기 위해 경고를 모두 감춤 |
| 연습 저장 실패 | 수행 표시는 아직 저장 확인 전 | 낙관적 완료와 별도의 실패 토스트가 충돌 |
| 연습 저장됨 | 본인이 표시한 연습 기록이 남음 | 숙달·발음 정확성·실력 향상을 자동 선언 |

여러 기능이 각자 성공·오류 토스트를 띄우는 대신, 사용자가 보고 있는 단계 가까이에 우선 상태와 회복 행동을 둔다. 자료를 읽고 있는 사용자의 스크롤을 비동기 완료가 임의로 움직이면 안 된다. 자동 갱신과 사용자가 요청한 단계 전환의 포커스 정책을 구분한다.

## 5. 검증 기준과 남은 불확실성

구현 검증에서는 통화 길이와 무관하게 회차 결과가 원문보다 먼저 있는지, 한 번의 조작으로 연습이 시작되는지, 서버 확인 후 완료 화면만 남는지, 뒤늦은 분석이 다른 탭·상대를 침범하지 않는지 확인한다. 오류 재시도에서 중복 분석·복습 기록이 생기지 않는 안전장치도 유지한다.

390px와 320px, 짧은·긴 문장, 긴 대화문, 저장·분석 지연, 무발화, 부분 전사, 실패·재시도, 연습 저장 실패, 재방문을 확인한다. 긴 실제 내용에서는 자연 세로 스크롤을 허용하되 가로 넘침·텍스트 잘림·도크 가림·초점 손실을 허용하지 않는다. 스크린샷은 배치의 증거이고 키보드·보조기술 동작은 별도 검증 대상이다.

실사용자에게는 먼저 정답을 알려 주지 않고 ‘방금 통화는 어떤 상태인가’, ‘이번에 가져갈 표현은 무엇인가’, ‘연습하거나 마치려면 어디를 누르는가’를 설명하게 하는 짧은 과제 검증이 필요하다. 연습 버튼을 많이 눌렀다는 사실만으로 효과적이라고 결론 내리지 않는다. 사용자의 의도와 달리 눌렀거나 실패해 반복한 것일 수 있다. 이번 배포의 기능·시각 검증을 이해도 향상 또는 학습 효과의 인과 증거로 대체하지 않는다.
