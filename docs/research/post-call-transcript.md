# 통화 종료 후 대화문: 근거와 검증 경계

조사일: 2026-11-10 UTC. 범위는 통화를 마친 뒤 수신된 대화문을 바로 열어 복습할 수 있게 하는 동작, 전사·저장 상태, 그리고 학습효과 주장의 타당성이다. 제품 코드는 이 조사에서 변경하지 않았다.

**판단:** 이미 받은 대화문을 종료 직후 볼 수 있게 하는 동작은 사용자가 명시한 접근 요구와 작업 상태의 가시성에 근거해 유지할 수 있다. 다만 **자동 대화문을 바로 보여주면 영어 말하기 실력이 향상된다**, **통화 후 교정이 통화 중 교정보다 항상 낫다**는 결론을 뒷받침하는 근거는 확보하지 못했다. 직접 전사하고 수정하는 학습 활동, 준비된 영상의 자막, 자동 전사문 읽기는 서로 다른 처치다.

## 조사 방법과 확인 수준

- 연구 논문의 출판사 원문·초록, 학술지 공식 공개 PDF, W3C 원문을 우선 확인했다. DOI는 출판사 및 Crossref 기록과 대조했다. 검색 결과의 논문 소개나 생성된 요약은 근거로 사용하지 않았다.
- Winke 외(2010)는 공식 공개 PDF의 방법·결과를 확인했다. Li 외(2026)는 공개 원문의 방법·결과·한계를 확인했다. 아래에서 초록만 확인한 연구는 그 범위를 명시했다. 확인하지 못한 표본 수·효과크기·장기 결과를 채우지 않았다.
- 현재 구현에 대한 기술적 사실은 [기존 변경 기록](../call-experience-improvements-20261110.md), [종료 처리](../../web/app.js), [대화문 화면](../../web/post-call-transcript.js), [기존 브라우저 검증 코드](../../test/end-transcript.browser.mjs)를 읽어 확인했다. 이번 문서는 새 사용자 조사, 실제 통화 실험, 화면 감사 또는 재실행한 테스트의 결과가 아니다.

## UX·접근성 근거

**규범과 설명을 구분한다.** [WCAG 2.2 SC 4.1.3](https://www.w3.org/TR/WCAG22/#status-messages)은 화면의 상태 메시지를 보조 기술이 초점 이동 없이 알릴 수 있도록 역할·속성으로 판별 가능하게 할 것을 요구한다. [W3C Understanding 문서](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)는 대기·진행·성공·오류 알림을 설명하는 비규범 해설이다. 대화문 본문 자체와 “서버 저장 대기/확인 실패” 같은 상태 메시지는 같지 않다. 매 발화를 강한 알림으로 읽게 하라는 요구도, 대화문을 의무적으로 즉시 열라는 요구도 아니다.

[NN/g의 시스템 상태 가시성 해설](https://www.nngroup.com/articles/visibility-system-status/)은 사용자의 동작이 수신되었는지, 작업이 진행 중인지 알 수 있게 피드백할 것을 권한다. 이는 전문가 UX 지침이며 이 앱의 전환율·불안 감소·학습 향상을 측정한 실험 결과가 아니다. 여기서 도출하는 설계 판단은 **“종료 요청 수신”, “받은 대화문 표시”, “전사 마무리”, “기기 보관”, “서버 저장”, “피드백 생성”을 하나의 완료 표시로 합치지 않는다**는 것이다. 특정 대기 초 수를 이 자료에서 도출하지 않는다.

| 마지막 전사가 도착하면 같은 통화에 보충하되 아직 안 받은 말을 만들어 보이지 않음 | 데이터 정확성·기능적 무결성 | 현재 단계·발화별 저장 표기, 늦은 전사 병합, 세션 범위 검사를 확인. 전사 완료는 의미 정확성 확인과 다름. |

| 사용자가 고른 대화문/피드백 보기 상태를 후속 저장 응답이 덮어쓰지 않음 | 사용자 작업 보존에 대한 설계 판단 | 현재 펼침 상태와 대화문 내부 주요 초점은 렌더링 때 보존하도록 작성되어 있음. 키보드·보조 기술에서의 실제 동작 확인은 필요. |
| 읽기만 한 것을 교정 습득·유창성 향상으로 집계하지 않음 | 관찰·선호·단기 수행·장기 학습을 구분하는 연구 결과 | 대화문 열람 수는 접근/사용 지표. 별도 말하기 과제의 지연 성과 없이 학습 성공으로 보고하지 않음. |

이 검토는 현재 접근 기능을 되돌릴 근거를 제시하지 않는다. 추가 UI, 자동 교정 정책, 기본 복습 과제, 강제 재발화는 아직 이 문서에서 확정하지 않는다. 특히 “사후이므로 인지부하가 줄어든다”는 설명은 검증할 가설이며 사용자에게 보장할 효과가 아니다.

아래는 논문이 정한 성능 수치가 아니라, 기존 요구를 검사 가능하게 표현한 제품 기준이다. 기존 자동 검증 코드는 구현의 분리·복원 시나리오를 다루지만 실제 사용자 품질의 대체물이 아니다.

| 과제·상황 | 관찰할 값 | 판정 기준 |

## 추가 설계에 필요한 증거

**접근 사용성과 학습효과의 문턱을 나눈다.** 먼저 실제 대상 학습자에게 통화 직후 “방금 한 표현 찾기”, “내 발화와 상대 발화 구분”, “현재 기기/서버 저장 여부 설명”, “일부 전사 누락과 잘못 인식된 표현 알아차리기”, “최근 통화에서 다시 찾기”를 수행하게 하는 소규모 형성 평가가 적합하다. 초급·중급, 모바일, 키보드·화면 읽기 프로그램 사용 환경을 포함한다. 표본을 모집하거나 사용자에게 연락하는 작업은 이번 조사에서 하지 않았다.

- 과제별 성공/시도 수, 성공까지 시간, 추가 조작 수, 잘못된 완료 판단 수, 인식 오류를 자기 영어 오류로 믿은 횟수를 기록한다. 인터뷰의 “편하다”와 실제 찾기 성공은 별도 결과로 보고한다.
- 주관적 정신적 노력·혼란·수정 자신감을 같은 척도로 비교하되, 만족도를 학습 점수로 바꾸지 않는다. 화면에 정보가 더 많아져 대화문 찾기를 방해하는지도 관찰한다.
- ASR 품질은 동의받은 별도 평가용 녹음의 사람 전사와 비교해야 한다. 전체 WER뿐 아니라 뜻·부정·수치·명사/동사 형태, 한영 전환, 오류의 자동 정상화를 분류한다. **현재 제품이 원본 음성을 저장하지 않는 상태에서 정확한 발화 진위를 사후 복원할 수 있다고 가정하지 않는다.** 이 평가는 실제 저장 정책 변경이나 녹음을 자동 승인하지 않는다.

학습 활동을 추가하려면 그다음에 **자동 전사 열람**, **표적 자기 수정**, **수정 후 새 맥락에서 재발화** 중 무엇을 비교할지 먼저 정해야 한다. 교정 정확성을 사람 평가로 검증하고, 동일한 연습 시간·발화 기회·피드백 양을 맞춘 뒤, 사전·즉시·지연 평가와 새로운 말하기 과제를 사용한다. 평가자는 가능한 한 조건을 모르게 하고, 정확성·유창성·내용 이해를 별도 채점한다. 최소한 의미 있는 차이와 분석 계획을 먼저 정한 다음 표본 수를 산정한다. 논문의 효과크기를 이 앱에 그대로 옮겨 표본 수나 기대 개선율을 만들지 않는다.

새 설계·구현으로 넘어갈 충분한 근거는 해당 변경의 목표에 맞춰 판단한다. **기존 대화문 접근 요구와 재현된 상태 표시 오류는 요구·상태 모델·기능 기준을 근거로 구현·수정할 수 있으며, 학습효과 실험이 그 수정을 막지는 않는다.** 실제 사용성은 별도로 확인한다. **학습에 더 좋다는 기본 정책·효과 주장은 교정 안전성과 지연·전이 성과까지 확인한 뒤** 판단한다. 현재 문헌은 전자의 설계 근거와 후자의 연구 방향을 제공하지만, 후자의 제품 효과를 이미 입증하지는 않는다.
