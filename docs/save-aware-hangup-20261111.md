# 실제 저장 확인에 맞춘 종료 화면

2026-11-11 KST. 고정 0.6초 전환을 저장 완료에 연동한다.

## 현재 알 수 있는 시간

통화 중에도 완료된 발화는 계속 기기와 서버에 저장된다. 종료 후 시간은 전체 음성 업로드 시간이 아니라 남은 전사·기기 큐·서버 반영·통화 종료 응답을 확인하는 시간이다.

열린 데이터 채널의 기존 종료 경로는 1.8초의 마지막 이벤트 수신 대기, 미완료 전사가 있을 때 최대 약 8초의 추가 대기(150ms 간격 확인), 기기 큐 처리와 서버 요청으로 구성된다. 네트워크 시간은 별도이므로 1.8초를 실제 평균이라고 하거나 9.8초를 전체 상한으로 말할 수 없다. 피드백은 통화 저장 확인 후 별도로 시작된다.

기존 운영 DB에는 종료 버튼을 누른 시각과 브라우저가 저장 응답을 받은 시각의 쌍이 없다. 세션 종료 시각·마지막 발화 시각·서버 입력 시각을 서로 빼서 실제 저장 지연의 평균이나 백분위로 제시하지 않는다.

## 변경된 동작

- 종료 즉시 마이크·상대 음성·일반 조작·아바타를 정지하고 종료음을 재생한다.
- 마지막 전사 완료, 기기 저장 작업 완료, 해당 통화 전송 큐 소진, 해당 통화의 유효한 종료 응답을 확인한 뒤 대화문으로 자동 이동한다. 응답은 같은 세션 ID, ended 상태, 유효한 종료 시각을 확인한다.
- 종료음 연출의 최소 시간은 600ms다. 실제 저장 확인이 더 늦으면 확인 직후 이동하며, 600ms를 저장 처리 시간 뒤에 추가하지 않는다.
- 대기 중에는 마지막 발화 정리/서버 저장 단계를 안내하고 경과 시간을 표시한다. 3초 후에는 ‘대화 내역 먼저 보기’를 제공한다. 먼저 읽는 동안에도 저장은 계속되며 완료로 표시하지 않는다.
- 최신 배포본의 통화 후 화면 구성을 유지한다. 저장 완료 후 자동 이동은 결과 제목에 초점을 두고 대화문은 접어 둔다. 사용자가 ‘대화 내역 먼저 보기’를 선택했을 때는 대화문을 바로 펼친다.
- 기존 10초 이후 ‘홈에서 기다리기’와 부분 저장·실패 복구를 유지한다. 사용자가 먼저 보기를 선택한 뒤 홈으로 이동했으면 저장 완료가 화면을 다시 끌어오지 않는다.
- 종료 처리 진입 시점부터 확인된 저장 응답까지 performance.now로 측정한다. 성공한 현재 통화의 대화문에 소요 시간을 표시한다. 최소 연출 시간과 피드백 생성 시간은 측정에 포함하지 않는다.
- 이 측정은 현재 통화의 화면에만 보관한다. 재접속한 과거 기록에 없는 소요 시간을 추정해서 표시하지 않으며, 추가 서버 분석 이벤트나 대화 내용 수집은 도입하지 않는다.

600ms/3초/250ms 갱신 간격은 제품 설정값이다. 브라우저 fixture의 지연은 실제 서비스 평균이나 사용자 관찰 결과가 아니다. 검증에서는 저장 응답을 의도적으로 지연·실패·변형하고, 실제 큐와 화면이 완료를 조기에 주장하지 않는지 확인한다.

승인 계정의 실제 음성 통화 시간은 이번 작업에서 새로 측정하지 않았다. 배포 후 현재 통화의 대화문을 펼치면 그 통화에서 직접 측정된 값을 확인할 수 있다.
