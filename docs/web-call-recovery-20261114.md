# 웹 통화 연결 복구

작업일: 2026-11-14 KST. 시작 소스 `322ccd0`, 공개 웹의 앱 소스는 `ef11416d7ffc556d2b6aa209d002f5adf441fd2e`와 동일했다. 제보 증상은 PC Chrome·Edge에서 ‘전화 거는 중’에 머무르는 것이다.

## 확인한 연결 오류

최근 48시간의 운영 메타데이터를 읽기 전용으로 집계했다. 현재 공개 빌드의 수동 경로 준비 작업 3건 모두 RTC 연결 기록 뒤 `server_vad:on → semantic_vad:off` 순서의 설정을 받았고, 통화 경과 0초에 `TURN_CONTROL_UNCONFIRMED`를 기록했다. 준비 작업·진단 수는 실제 사용자 수나 정상 통화 수가 아니며, 이 기록을 제보자의 특정 통화와 연결한 것은 아니다. 사용자 ID·이메일·원문·SDP는 가져오지 않았다. [집계](design/web-call-recovery-20261114/production-aggregate.json).

기존 앱은 RTC와 데이터 채널이 열리면 바로 통화와 수동 응답 제어를 시작했다. 이후 초기 기본 자동 감지 설정을 받으면 수동 controller가 오류 상태를 고정했고, 정상 수동 설정이 도착해도 첫 응답을 만들지 못했다.

운영과 같은 이벤트 순서를 모의해 기존 앱과 수정 앱을 비교했다. 기존 공개본과 동일한 소스에서는 설정 확인 전 시계가 시작되고, 정상 설정 뒤에도 첫 응답 0회·오류 1회였다. 수정본은 설정 ACK 전 시계 00:00을 유지하고, 일치하는 ACK 뒤 첫 응답 1회·오류 0회였다. 인증·backend·provider·RTC는 모의 전송이며 실제 음성 통화 결과는 아니다. [전후 비교](design/web-call-recovery-20261114/policy-before-after.json).

또한 다음 복구 공백을 재현했다.

- SDP 응답 이후 ICE 또는 데이터 채널이 끝내 열리지 않으면 초기 연결 전체의 종료 기한이 없었다.
- 일부 브라우저에서 `AbortSignal.any/timeout` 또는 `Map.groupBy`가 없으면 음성 요청 전 취소 처리·대화 저장 동기화가 실패할 수 있었다. 이것이 제보자의 PC 브라우저 원인이라고 단정하지 않는다.
- 자동재생 차단 뒤 ‘화면을 눌러 다시 재생’ 안내가 있었지만 실제 재시도 동작은 없었다. 같은 stream이 이미 연결돼 재생을 다시 시도하지도 않았다.

## 변경

1. 데이터 채널에서 원하는 수동 정책을 명시적으로 요청하고, provider의 필수 설정 ACK를 확인한 뒤 인사·마이크·통화 시간을 시작한다. 초기 기본값만으로 수동 controller를 시작하지 않는다. 잘못된 ACK나 미확인 상태는 연결 단계에서 정리하고 재시도할 수 있다.
2. 마이크 권한을 받은 뒤 초기 연결에만 45초 기한을 적용한다. 세션 저장·offer·SDP·RTC·데이터 채널의 끝없는 대기를 해제하고 트랙·연결을 정리한다. 실제 연결이 완료되면 이 기한은 영구 해제되며 진행 중 통화를 감시하거나 끊지 않는다. 취소 뒤 늦게 끝난 작업은 이전 시도를 되살리지 않는다.
3. 요청 취소·timeout을 호환 가능한 controller로 합성하고 저장 큐를 기본 Map 반복으로 그룹화한다. 전송 실패 시 원문 보존·동일 ID 재시도·계정/세션 경계는 유지한다.
4. 자동재생이 차단되면 실제 사용자 gesture에서 같은 통화의 같은 stream 재생을 다시 시도한다. 성공하면 차단 안내만 지우며 새 통화·새 인사를 만들지 않는다.
5. backend가 승인한 응답 지침과 provider가 보고한 설정을 분리한다. 기본값·속도 ACK·늦은 옛 echo가 승인 지침을 덮어쓰지 못하며, checkpoint의 현재 정확한 ACK만 새 지침으로 채택한다. 이 변경은 모델의 자연스러움 자체를 입증하지 않는다.

## 검증과 범위

초기 연결의 무한 대기·취소·정리·재시도·늦은 완료, 초기 기본 설정 뒤 올바른 ACK, 잘못된/없는 ACK, 최신 정적 API가 없는 환경, 자동재생 재시도를 실제 Chromium과 native 마이크 트랙·IndexedDB에서 검사한다. 전송은 명시적 fixture다. 같은 초기 정책 순서의 기존/수정 소스 비교와 390px·320px/큰 글자 화면을 별도로 확인했다.

정상 연결이 먼저 필요한 복구 릴리스다. 캐릭터의 관점·양쪽 화자 근거가 있는 대화 기억·기억 무효화의 안전한 재설정은 별도 고도화 단계에서 적용한다. 문장 수·인사 길이를 제한하거나 검증되지 않은 끼어들기 분류로 해결하지 않는다. 배포·공개 빌드 확인 결과는 완료 후 기록한다.
